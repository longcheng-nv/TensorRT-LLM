1. Design设计

The baseline GVR kernel refines its threshold with a secant search: each Phase-2 iteration is one full-N block_count_ge scan evaluating ONE threshold, accepting any count in [K, kC] (kC = 5120/6144 ≈ 2.5–10×K) — a loose accept that leaves Phase-4 a large candidate set. op18 replaces Phase-2 with an adaptive M-ary multi-threshold search, per the count_ge_multi_bench primitive and op17's band selection:

  • block_count_ge_multi<M> — ONE full-N scan evaluates M sorted thresholds: identical vectorized/4-way-unrolled memory path, M static register counters, M branchless predicated adds per element, M-column staged block reduce with a single barrier.
  • All M per-thread count columns cached in smem (column-major, M·threads·4 B ≤ 32 KB): the winning column is copied to smem_ptcnt, so Phase-3 collects with done=1 and zero recount — closing the “+1 extra scan” gap in the count_ge_multi design note.
  • CDF-aware placement (the decisive lever): round-1 thresholds are compile-time fracs on the preIdx band [pmin, pmax] (op17: count(pmin) ≥ K always), fit offline per (K, N, M) on 5 synth seeds to a geometric count ladder (scripts/optimize_fracs.py). fracs[0]=0 anchors exactness; M ≥ 3 is seed-safe.
  • Adaptive rounds: if the tightest count > c_accept, one refine round re-places M thresholds strictly inside the surviving bracket (round-2 pass is L2-warm). done=1 only when count ∈ [K, kC]; anything else falls back to the baseline's exact retry-shrink path.
  • Per-(K, N) dispatch (replaces kFTarget tuning): M4–M6 R1 at N ≤ 8K (latency-bound, compares free), M3 R1 at 16–65K, M2 R2 acc=2K at N ≥ 131K (M2 is the only tax-free width on a cold bandwidth-exposed pass).

基线 GVR 内核用割线搜索细化阈值：Phase-2 每次迭代都是一遍全 N 的 block_count_ge，只评估一个阈值，接受窗口 [K, kC]（kC = 5120/6144 ≈ 2.5–10×K）非常宽松，导致 Phase-4 候选集偏大。op18 依据 count_ge_multi_bench 原语与 op17 的带选择方法，将 Phase-2 替换为自适应 M 元多阈值搜索：

  • block_count_ge_multi<M> —— 一遍全 N 扫描同时评估 M 个有序阈值：内存路径与生产版完全相同（向量化 + 4 路展开），M 个静态寄存器计数器、每元素 M 路无分支谓词加、M 列一次 barrier 的分级归约。
  • 缓存全部 M 份每线程计数列（列主序 smem，M·threads·4 B ≤ 32 KB）：获胜列拷贝到 smem_ptcnt，Phase-3 以 done=1 收集，零重扫 —— 补上 count_ge_multi 设计笔记中“多一遍扫描”的缺口。
  • CDF 感知放置（决定性杠杆）：第 1 轮阈值是 preIdx 带 [pmin, pmax]（op17：count(pmin) ≥ K 恒成立）上的编译期分数，离线按 (K, N, M) 在 5 个种子上拟合几何计数阶梯（scripts/optimize_fracs.py）。fracs[0]=0 锚定精确性；M ≥ 3 对种子鲁棒。
  • 自适应轮数：若最紧计数 > c_accept，追加一轮在存活区间内部重新放置 M 个阈值（第 2 轮为 L2 暖数据）。仅当计数 ∈ [K, kC] 才 done=1；否则回落到基线的精确 retry-shrink 路径。
  • 按 (K, N) 分派（取代 kFTarget 调参）：N ≤ 8K 用 M4–M6 R1（延迟受限，比较免费），16–65K 用 M3 R1，N ≥ 131K 用 M2 R2 acc=2K（冷的带宽暴露遍上只有 M2 免税）。

2. Why naive multi-threshold fails: the L2 trap朴素多阈值为何失败：L2 陷阱

The first A/B (uniform placement, always-2-rounds) averaged 0.93× with 0.70× at 262K. clock64 phase timing (scripts/measure_mt_phases.py) localized it (K512/N262144, cycles):

baseline: P1 3.5K | P2 27.3K = COLD pass ~22K + L2-WARM pass ~5K | P3 29K | P4 10.2K
op18 M4R1: P1 3.6K | P2 33K (ONE cold M4 pass) | P3 28K | P4 15.3K

The baseline's “extra” secant passes are nearly free (row ≤ 1 MB ≪ 50 MB L2), while the M-compare tax rides the COLD pass and is latency-exposure-bound: branchless rewrites and unroll 8/16 changed nothing; in-kernel M-scaling equals the standalone microbench (M2 ≈ free, M4 ×1.46, M8 ×2.7 at 262K). Collapsing passes therefore buys only warm passes — the win must come from a tighter threshold in one near-free pass (P4 shrink), which is what CDF-aware placement delivers. A second discovery: P4 histogram-snap time is placement-sensitive, not cand-linear (7.2K vs 15.3K cyc at same-order cand).

第一次 A/B（均匀放置、固定 2 轮）平均只有 0.93×，262K 处 0.70×。clock64 分相计时（scripts/measure_mt_phases.py）定位了原因（K512/N262144，cycles）：

基线：  P1 3.5K | P2 27.3K = 冷遍 ~22K + L2 暖遍 ~5K | P3 29K | P4 10.2K
op18 M4R1：P1 3.6K | P2 33K（一遍冷 M4）| P3 28K | P4 15.3K

基线“多出来”的割线遍几乎免费（行 ≤ 1 MB ≪ 50 MB L2），而 M 路比较税落在冷遍上且属于延迟暴露受限：无分支重写与 8/16 路展开均无效；内核内 M 缩放与独立微基准一致（262K 处 M2 ≈ 免费、M4 ×1.46、M8 ×2.7）。因此“折叠遍数”只能省下暖遍 —— 收益必须来自一遍近免费扫描中拿到更紧阈值（P4 收缩），这正是 CDF 感知放置的作用。另一发现：P4 直方图-snap 时间对阈值位置敏感，并非只随候选数线性（同量级候选 7.2K 对 15.3K cyc）。

7. Honest bounds & relation to op17诚实边界与 op17 的关系

  • Peak BS=1 speedup is below op17's cooperative-cluster portfolio (nsys 1.10–1.45× vs 1.21–1.67×): a single CTA cannot scan redundantly for free, so the tight threshold costs an M-compare tax instead of idle-SM bandwidth. op18's value is robustness: single-CTA (no cluster machinery, no G=2 instability), wins at ALL BS, all dtypes, zero regression.
  • Weakest cells: K1024/4K (~1.02×) and K2048/16K (~1.01×) — near-neutral, not losses.
  • Fracs are fit on synth bundles; real DSv4 captures have different CCDF tails — refit before production (see LEARNINGS follow-ups).
  • BS=1 峰值加速低于 op17 的协作 cluster 组合（nsys 1.10–1.45× 对 1.21–1.67×）：单 CTA 无法免费冗余扫描，紧阈值要付 M 路比较税而不是白嫖空闲 SM 带宽。op18 的价值在鲁棒性：单 CTA（无 cluster 机制、无 G=2 不稳定），全 BS、全数据类型获胜，零回退。
  • 最弱单元：K1024/4K（~1.02×）与 K2048/16K（~1.01×）—— 近中性，非回退。
  • fracs 基于合成 bundle 拟合；真实 DSv4 捕获的 CCDF 尾部不同 —— 生产化前需重拟合（见 LEARNINGS 后续项）。
