1. 优化目标1. Optimization goal

围绕 SANDWICH 双阈值思想构建完整 GVR 优化桶:从 op18 的一次 M 叉阶梯扫描(block_count_ge_multi)中免费取得一对阈值——

  • thr0:计数 M0 < K 的最紧阈值 → 这 M0 个元素保证是 top-K 成员,P3 阶段直接写出;
  • thr1:计数 M1 ∈ [K, kC] 的接受阈值 → P4 只需在带 [thr1, thr0) 内的 M1−M0 个候选中精化余下 K−M0 个名额。

目标:最大化 M0、最小化 M1、压低 P2 轮数;变体覆盖单 CTA(扩展 op18)与多 CTA cluster(扩展 op17 portfolio);在 report 网格全部 720 个 B200 cell(K×dtype×N×BS)上击败单 CTA gvr_cutedsl,冲击平均 ≥1.5×(iter0 即声明:若地板数学证明不可达,则如实报告差距)。

Build a full GVR optimization bucket around the SANDWICH two-threshold idea: from op18's single M-ary ladder pass (block_count_ge_multi), obtain a threshold pair for free —

  • thr0: tightest threshold whose count M0 < K → those M0 elements are guaranteed top-K members, direct-written in P3;
  • thr1: the accepted threshold with count M1 ∈ [K, kC] → P4 only refines the band [thr1, thr0) of M1−M0 candidates for the remaining K−M0 slots.

Goals: maximize M0, minimize M1, keep P2 rounds low; variants cover single-CTA (extending op18) and multi-CTA cluster (extending op17's portfolio); beat single-CTA gvr_cutedsl on ALL 720 B200 cells of the report grid (K×dtype×N×BS), targeting ≥1.5× average (with the iter0 commitment: if floor math proves the target unreachable, report the gap honestly).

2. 最终算法2. Final algorithm

最终交付为三件套:两个内核策略 + 一张按 cell 完备的调度表。

Strategy-A — 单 CTA sandwich(src/gvr_sw_op.py, GvrSandwichKernel)

  1. P2 = 一次 M 叉阶梯扫描:一遍全 N 扫描同时评估 M 个阈值(向量化、逐元素 M 谓词加,单次 M 列 barrier),阈值位置来自离线 straddle-fracs(每 (K,N,dtype,M) 5 种子优化:{0 锚点, l1=全种子 count≥K 的最大 frac, l0=全种子 count<K 的最小 frac, 内插点},保证从两侧夹住 vK);全部 M 列 per-thread 计数缓存于 smem,P3 零重算。
  2. P3 = sandwich 收集:单个稀有外层分支 if v≥thr1 内嵌分类(≥thr0 → 直写候选;带内 → smem);两个前缀和打包进一个 warp scan((up<<16)|band);defer-direct:直写索引先缓冲 smem,barrier 后合并冲刷(避免散射存储打断 4 路 LSU 流水,iter5 教训)。
  3. P4 = 带内 band-snap:runtime-k(k_rem = K−M0)+ 直方图范围以 [thr1, thr0) 播种,工作集从数千候选坍缩到数十。
  4. 接受条件是 band≤kC 而非 M1≤kC(smem 只装带内),M1 超 kC 的 cell(如 K2048/65K M1≈6.6K)照常 sandwich;无对/超界时 done=2 精确 retry-shrink,无静默截断。

Strategy-B — 多 CTA cluster sandwich(src/gvr_swc_op.py, 承自 op17)

G 个 slot 按 straddle-aware fracs {0 锚点} + linspace(l1,l0,G−1) 布点;DSMEM 共享计数;所有 rank 同时计算阈值对(r1=最紧 ≥K,r0=r1+1 <K);胜者 CTA 经 DSM 拷贝 r0 的 per-thread 计数列后,直写 CTA 与带内精化 CTA 并发工作(thr0 列就在其自身 smem,零额外 DSMEM 拷贝)。顺带修复 op17 D0 exactness bug(count>kC 时 P3 静默截断 → 改为 done=2 retry-shrink)。

Strategy-C — 按 (K,N,BS,dtype) 完备调度

The final deliverable is a triple: two kernel strategies + a per-cell-complete dispatch table.

Strategy-A — single-CTA sandwich (src/gvr_sw_op.py, GvrSandwichKernel)

  1. P2 = one M-ary ladder pass: a single full-N scan evaluates M thresholds simultaneously (vectorized, per-element M-predicated adds, one M-column barrier). Threshold placement comes from offline straddle-fracs (per (K,N,dtype,M), optimized over 5 seeds: {0 anchor, l1 = max frac with count≥K on all seeds, l0 = min frac with count<K on all seeds, interpolated inner points} — guaranteed to bracket vK from both sides). All M per-thread count columns are cached in smem; P3 recounts nothing.
  2. P3 = sandwich collect: one rare outer branch if v≥thr1 with nested classification (≥thr0 → direct-write candidate; in-band → smem); both prefix sums packed into ONE warp scan ((up<<16)|band); defer-direct: direct indices are buffered in smem and flushed coalesced after the scan barrier (scattered stores inside the hot loop broke the 4-way LSU pipeline — iter5 lesson).
  3. P4 = in-band band-snap: runtime-k (k_rem = K−M0) + histogram range seeded with [thr1, thr0); the working set collapses from thousands of candidates to tens.
  4. Acceptance is band≤kC, not M1≤kC (smem only holds the band), so cells whose tightest M1 exceeds kC (e.g. K2048/65K, M1≈6.6K) still sandwich; no-pair/overflow → done=2 exact retry-shrink, no silent truncation.

Strategy-B — multi-CTA cluster sandwich (src/gvr_swc_op.py, inherited from op17)

G slots placed at straddle-aware fracs {0 anchor} + linspace(l1,l0,G−1); DSMEM count sharing; all ranks compute the pair (r1 = tightest ≥K, r0 = r1+1 <K); after the winner DSM-copies r0's per-thread count column, the direct-write CTA and the band-refine CTA work concurrently (the thr0 column lives in that CTA's own smem — zero extra DSMEM copies). op17's D0 exactness bug fixed en passant (count>kC silent P3 truncation → done=2 retry-shrink).

6. 关键教训(证伪记录)6. Key lessons (falsification log)

  • ACTIVE-SET L2 陷阱:判断 baseline 额外遍是否"真冷",看的是活跃集(SM×驻留CTA×行字节)对 L2 的溢出,与 batch 总量无关。这一修正把"高 BS 必赢"改写为"高 BS × N≥131K(fp32)才赢"。
  • 占用率是双向一等变量(iter14):−8 KB smem"白捡"却把驻留从 2 抬到 3 CTA/SM,L1/LSU 争用反亏 19%;任何 smem/寄存器变化都要 A/B 驻留档位。
  • 热循环里的第二个分支比多算一遍更贵(iter5/7):散射存储与 if/elif 链都会打断 LSU 流水;稀有外层分支 + 延迟合并冲刷是标准解法。
  • 调度表的空键 = 隐性回退(iter16):88 键表让 152/240 cell 落到默认配置,而表内预测零失误——全部亏损来自"没测过的桶"。完备化(240 键)+ 亏损桶硬化 baseline 是廉价且彻底的修复。
  • 16-bit 不是免费的 fp32(iter9/11):行字节减半外扩 L2-warm 区间(bf16 K2048 中 N 结构性输)且需原生 straddle-fracs 表;dtype 是调度维度,不是编译细节。
  • The ACTIVE-SET L2 trap: whether the baseline's extra passes are "truly cold" depends on the active set (SMs × resident CTAs × rowbytes) spilling L2 — not on total batch size. This rewrites "high-BS always wins" into "high-BS × N≥131K (fp32) wins".
  • Occupancy is a first-class, bidirectional variable (iter14): a "free" −8 KB smem saving lifted residency 2→3 CTAs/SM and lost 19% to L1/LSU contention; every smem/register change must be A/B'd across residency tiers.
  • A second branch in the hot loop costs more than an extra pass (iter5/7): scattered stores and if/elif chains both break the LSU pipeline; one rare outer branch + deferred coalesced flush is the standard fix.
  • Empty dispatch keys are silent fallbacks (iter16): the 88-key tables sent 152/240 cells to the default config while in-table predictions had zero misses — every loss came from an unmeasured bucket. Completing the table (240 keys) + hardening losing buckets to baseline is the cheap, thorough fix.
  • 16-bit is not free fp32 (iter9/11): halved rowbytes extend the L2-warm regime (bf16 K2048 mid-N loses structurally) and need native straddle-frac tables; dtype is a dispatch dimension, not a compile detail.

7. 诚实差距与下一步:让 GVR 在 Blackwell 全域最优7. Honest gap & next steps: making GVR optimal everywhere on Blackwell

诚实差距 — 720 cell 平均 ≥1.5× 未达成(实测 gm 1.122×)。这与 op12 的地板分析一致:小 N 受 barrier 地板(P1–P3 ≈1.2× SGLang 下限)、BS=1 大 N 受 L2 陷阱(baseline 第二遍近乎免费)约束,二者共同压低全网格均值;1.5× 只在"活跃集溢出 L2"的高 BS×大 N 象限内可达(该象限实测 1.4–1.86×)。在纯 GVR 家族内继续堆单点优化无法改变这个结构。
Honest gap — the ≥1.5× 720-cell average was not met (measured gm 1.122×). Consistent with op12's floor analysis: small-N is barrier-floor-bound (P1–P3 ≈1.2× of the SGLang lower bound) and BS=1 large-N is L2-trap-bound (the baseline's second pass is nearly free), jointly capping the grid mean; 1.5× is only reachable inside the high-BS × large-N quadrant where the active set spills L2 (measured 1.4–1.86× there). No amount of point optimization inside the pure GVR family changes this structure.

要在所有 seq_len × BS × dtype × top-K 上成为最优,路线按预期收益/风险排序:

  1. 跨家族组合调度(收益最大、零内核工作):本工作已证明"表驱动按 cell 调度"的机制有效(表内预测零失误)。把调度键的取值从 {sandwich 配置, cluster, baseline} 扩到 {…, radix_cutedsl, streaming_topk}:BS=1 段交给 radix(耗时比 0.53–0.77)、中小 N 高 BS 段可用 streaming、其余归 sandwich。以各家族全网格实测直接填表即可,预计把"全域最优缺口"一次性关死——代价是维护两套内核的 exactness 门与 preIdx 契约适配。
  2. GVR 自身的 BS=1 并行度补课:radix 在 BS=1 赢在每行 4–32 CTA 的读带宽。cluster sandwich 目前 G 个 CTA 冗余扫同一行(拿并行度换阈值组合),下一步让 G 个 CTA 分段扫行(每 CTA 1/G 行 + DSMEM 计数归约),P2 遍时间除以 G——这是把 radix 的分块思想移植进 GVR 阈值机制,保留 preIdx 带播种优势。风险:分段计数归约的 barrier 链可能吃掉小 N 收益(op17 iter5 双核方案 0.63–0.84× 的前车之鉴,但那是跨 launch,cluster 内 DSMEM 归约无此开销)。
  3. 中 BS(32–128)空档:pick_G 约束 bs×G ≤ SMs/2 使 BS≥32 时 G=1,而 pass-collapse 又要 N≥131K 才付账。行配对 cluster(2 行共享一个 G=2 组,DSMEM 各自计数)可在 BS 32–128 × N 32–131K 的空档内把活跃集×并行度同时抬高;需先离线仿真验证驻留档位。
  4. bf16/K2048 结构域:行字节减半 → 活跃集更难溢出 L2 → pass-collapse 无账可付。对策是每 CTA 多行粗化(单 CTA 串行处理 2–4 行,活跃行数×2–4,行间复用阈值表),把"溢出点"拉回中 N;或该域永久 baseline(当前方案,零风险)。
  5. 运行时自适应 fracs:离线 straddle 表是对合成分布的拟合;线上流量分布漂移会侵蚀 M0/K。以 EMA 跟踪实测 (M0, M1) 并微调 frac 锚点(P1 内标量工作,~0 开销),换取真实服务负载下的鲁棒性;可与 dsv4 真实 capture(§C/§D)回放先行验证。
  6. P4 叠加 rank-scatter(op#7):带内 snap 与 rank-scatter 正交——带内候选数十时 snap 已近地板,但 K2048 大带 cell(band 数百)仍可能吃到 P4 相 1.1–1.5×;一次 A/B 即可裁决。
  7. 协议提醒:以上任何单点在宣称收益前必须过三关——exactness 门 → cold-L2 event → nsys 纯核;并对照 gvr_phase_timing/ 的 12 条已证伪路径与本文 §6,避免重走死路。

To become optimal on every seq_len × BS × dtype × top-K, the roadmap ordered by expected gain/risk:

  1. Cross-family portfolio dispatch (largest gain, zero kernel work): this work proved the table-driven per-cell dispatch machinery (zero in-table prediction misses). Extend the key's value set from {sandwich configs, cluster, baseline} to {…, radix_cutedsl, streaming_topk}: hand BS=1 to radix (time-ratio 0.53–0.77), small-to-mid N × high BS optionally to streaming, the rest to sandwich. Populate directly from each family's measured fullgrids — expected to close the "optimal everywhere" gap in one move; the cost is maintaining exactness gates and preIdx-contract adaptation for two extra kernel families.
  2. Fixing GVR's own BS=1 parallelism deficit: radix wins BS=1 through 4–32 CTAs/row of read bandwidth. The cluster sandwich currently has G CTAs scan the same row redundantly (spending parallelism on threshold portfolio); next, let G CTAs scan row segments (1/G row each + DSMEM count reduction), dividing P2 pass time by G — porting radix's chunking into the GVR threshold machinery while keeping the preIdx band advantage. Risk: the segmented-count reduction barrier chain may eat the small-N gain (op17 iter5's two-kernel attempt hit 0.63–0.84×, but that was cross-launch; intra-cluster DSMEM reduction has no such overhead).
  3. The mid-BS (32–128) gap: pick_G's bs×G ≤ SMs/2 forces G=1 at BS≥32, while pass-collapse only pays at N≥131K. Row-paired clusters (2 rows share a G=2 group, per-row DSMEM counts) can lift active-set × parallelism simultaneously in the BS 32–128 × N 32–131K void; validate residency tiers in offline sim first.
  4. The bf16/K2048 structural regime: halved rowbytes → the active set spills L2 later → pass-collapse has nothing to collect. Counter with multi-row-per-CTA coarsening (one CTA serially handles 2–4 rows, ×2–4 active rows, threshold tables reused across rows), pulling the spill point back to mid-N; or keep the permanent baseline fallback (current solution, zero risk).
  5. Runtime-adaptive fracs: offline straddle tables fit the synthetic distribution; live-traffic drift erodes M0/K. Track realized (M0, M1) with an EMA and nudge the frac anchors (scalar work in P1, ~zero cost) for robustness on real serving load; validate first by replaying the real DSv4 captures (§C/§D).
  6. Stack rank-scatter (op#7) into P4: the in-band snap and rank-scatter are orthogonal — with tens of in-band candidates snap is near its floor, but K2048 wide-band cells (hundreds) may still take the 1.1–1.5× P4-phase gain; one A/B settles it.
  7. Protocol reminder: any of the above must pass three gates before claiming gains — exactness gate → cold-L2 event → nsys pure-kernel — and be checked against the 12 falsified paths in gvr_phase_timing/ plus §6 here, to avoid re-walking dead ends.
