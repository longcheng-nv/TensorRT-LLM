1. Era-0: GVR 的诞生(2026-01 ~ 03, custom_indexer_topK/)

1.1 时间线要点

  • 01-25:起点 = 精确分层归约 top-K(CUB BlockRadixSort);同日迭代为 warp-level Top-L + block merge。动机:B200 上 device radix sort 在 K=2048、N<32768 输给 on-chip 选择。
  • 01-26/27:GVR 胚胎 + preidx 首次出现(onchip_topk_preidx_bak/USAGE.md):阈值 T=min(dedup preidx) → 扫描收集 ≥T → merge,溢出 full-scan 兜底,附精确性证明。preidx 复用(temporal hint)这一核心 premise 是人的假设。
  • 02-02:双 LLM 同题竞赛——gemini(bitonic 流式 merge,sort-based)1 天出局;Claude 的 sort-free 阈值系获全部后续投资。
  • 02-09:GVR 完整形态首现(onchip_topk_preidx_claude_bak/heuristic_topk.cuh):P1 preidx min/max → P2 插值搜索 T 使 count∈[K, MAX_CAND] → P3 单 pass collect → P4 selection。op7~op27 一切工作的直系祖先。
  • 02-12:V1 插值法被集中分布 (1+0.1·N[0,1]) 灾难性证伪(CDF 近垂直、反复 overshoot、最多 6 次全局扫描)→ 三条 refine 支线并行:secant+damping(v2 主线)/ 两级 256-bin 直方图 / FD-Newton。
  • 02-13:真实数据首次进场(DSv3.2 SWE-64K Layer 20/40)。此前全靠 distype 0-5 合成分布 + Am-noise preidx 模型。
  • 03-02~03-15:v2 主线定型 V2d-final(secant 阻尼 + bisection 兜底 + ballot-free collect + 256-bin hist + snap≤3);ALGORITHM.md 充分性定理 = 今日 GVR 正确性论证原型。
  • 03-10→03-12:进 TRT-LLM 生产(torch.ops.trtllm.indexer_topk_decode);性能测试与边界正确性 UT 重写相隔一个月——正确性契约是集成时才补的账。

1. Era-0: the birth of GVR (2026-01 ~ 03, custom_indexer_topK/)

1.1 Timeline highlights

  • 01-25: starting point = exact hierarchical-reduction top-K (CUB BlockRadixSort); iterated the same day into warp-level Top-L + block merge. Motivation: on B200, device radix sort loses to on-chip selection at K=2048, N<32768.
  • 01-26/27: GVR embryo + first appearance of preidx (onchip_topk_preidx_bak/USAGE.md): threshold T=min(dedup preidx) → scan-collect ≥T → merge, full-scan fallback on overflow, with an exactness proof. The preidx-reuse premise (temporal hint) was a human hypothesis.
  • 02-02: dual-LLM same-problem bake-off — gemini's sort-based streaming bitonic merge was out in one day; Claude's sort-free threshold family received all subsequent investment.
  • 02-09: first complete GVR form (onchip_topk_preidx_claude_bak/heuristic_topk.cuh): P1 preidx min/max → P2 interpolation search for T s.t. count∈[K, MAX_CAND] → P3 single-pass collect → P4 selection. Direct ancestor of everything op7~op27.
  • 02-12: the V1 interpolation refine was catastrophically falsified by a concentrated distribution (1+0.1·N[0,1]: near-vertical CDF, repeated overshoot, up to 6 global scans) → three refine branches in parallel: secant+damping (v2 mainline) / two-level 256-bin histogram / FD-Newton.
  • 02-13: real data enters for the first time (DSv3.2 SWE-64K layers 20/40). Everything before ran on distype 0-5 synthetic distributions + the Am-noise preidx model.
  • 03-02~03-15: v2 mainline solidifies into V2d-final (damped secant + bisection fallback + ballot-free collect + 256-bin hist + snap≤3); ALGORITHM.md sufficiency theorem = the prototype of today's GVR correctness argument.
  • 03-10→03-12: lands in TRT-LLM production (torch.ops.trtllm.indexer_topk_decode); the perf test and the boundary-correctness UT rewrite are a month apart — the correctness contract was back-filled at integration time.

1.2 Human/LLM division of labor

Human: problem setup (exact/unordered/K=2048/single-CTA), the preidx premise, baseline choice, opening and judging the dual-LLM A/B, synthetic-distribution matrix design, the pivot to real data, opening and judging the three refine branches, production integration. LLM: all kernel code and per-phase micro-optimizations (V2a→V2d), the ALGORITHM.md math docs. Physical evidence: the topk_ext.cu comment "Optimization Constants requested by user"; the 03-05 CLAUDE.md + the user's first self-authored SKILL.md on 03-12 = the germ of moving from "using an LLM to write kernels" to "building infrastructure for agents".

1.3 Era-0 lessons

  1. The "threshold as root-finding" abstraction was fixed in week 2; the following 5 months optimized the root-finder and the data model, never the skeleton — early direction choice (human) has far more leverage than kernel micro-optimization (LLM).
  2. Dual-LLM bake-offs are cheap and verdicts come fast — the value of a control arm is rapid falsification, not fair comparison.
  3. Every algorithmic crisis came from data distributions, never from hardware — test-distribution coverage should expand ahead of kernel iteration.
  4. The correctness contract was absent during prototyping and paid back in one lump at integration — the later exactness-gate-first discipline is the direct correction.
  5. Snapshot-style evolution without version control left provenance recoverable only by mtime archaeology — the cautionary tale behind the per-iter commit discipline.

2.1 方法论演进的四个转折点

  1. 04-06 clock64 相位计时上线(复用 write-only scratch 零新增 HBM;首次落地花 15 turns 调试);数值立即用纯 Python CCDF 模拟交叉验证——"插桩数值必须有独立通道复核"从此建立。

  3. 05-08 F006 硬规则诞生:同一 SASS,standalone JIT(preIdxOffset=0)比生产 op 慢 20.9-34.4%——headline 数字只准走生产路径。同日 printf 污染事故:multi-CTA 全部 baseline 用了带 printf 的插桩 kernel(+25-45µs/launch),干净重测后"1.65-6.48× 胜"翻转为"全 cell 慢 1.5-3×",整份报告作废。
  4. 05-11 方法论合同成文(HOW_TO_BENCHMARK.md §5:128MiB L2 flush 每 launch 前、只报 median、preIdx[0]=行 argmax 等)。

三种计时工具最终分工:clock64=相内归因(禁做 baseline)/ nsys NVTX=一切 headline 仲裁 / cudaEvent=快速相对 Δ(launch floor ~12µs 占 70% wall,会误判 multi-CTA 类优化上限)。

2. Era-1: systematic ablation and the 12-negative-result ledger (2026-04-06 ~ 06-09)

Setting: systematic ablation of the V2e GVR kernel vs Radix on B200 (mainline question: the large-BS "death valley"). Output: the Scheme X production dispatcher, the 12+2 negative-result ledger, the cuteDSL port, and the embryo of every op-bench methodology. Authoritative ledger = 00_docs/STATUS.md (1108 lines) + KERNEL_OPTIMIZATIONS.md.

2.1 Four methodology turning points

  1. 04-06 clock64 phase timing lands (reusing write-only scratch, zero extra HBM; first landing took 15 debugging turns); numbers were immediately cross-checked with a pure-Python CCDF simulation — "instrumented numbers must be verified through an independent channel" was established here.
  2. 04-23 the cudaEvent vs nsys divergence is quantified (the turning point): host overhead is a constant (+6-8µs) for small kernels; the same kernel shows 1.65× (event) vs 1.93× (nsys). From then on nsys NVTX is canonical.
  3. 05-08 hard rule F006 is born: identical SASS, yet the standalone JIT harness (preIdxOffset=0) is 20.9-34.4% slower than the production op — headline numbers may only come from the production call path. Same day, the printf contamination incident: every multi-CTA baseline had used an instrumented kernel with printf (+25-45µs/launch); clean re-measurement flipped "1.65-6.48× win" into "1.5-3× slower everywhere" and the whole report was retracted.
  4. 05-11 the methodology contract is written down (HOW_TO_BENCHMARK.md §5: 128MiB L2 flush before every launch, medians only, preIdx[0]=row argmax, etc.).

Final division of the three timers: clock64 = intra-phase attribution (never a baseline) / nsys NVTX = arbiter of all headline numbers / cudaEvent = fast relative deltas (its ~12µs launch floor is 70% of the wall and misjudges the ceiling of multi-CTA-style optimizations).

2.2 Shipped items and the 12+2 negative results

Shipped: OPT4-7 (redux.sync, P3 count reuse, P4 two-step parallel search, smem count cache) + Q1b dtype paths + kFTarget retuning + Scheme X dispatcher v1.0→1.2 (zero data hard-coding, validated over 273k cells). Validation discipline: JIT snapshot quick test (~30s loop) → incremental rebuild only on positive signal → re-test on the production harness → revert negatives but archive raw CSVs.

Negative results fall into three root-cause classes: structural walls (FP16 scan cache / single-scan fusion / cp.async / L2-persistence / cluster DSM decided in 4 hours / P1 self-loop over 91,080 real cells / γ exp-bisect), measurement artifacts (the Oracle +51% misreading later explicitly corrected, printf contamination, the AIR-port architecture mismatch), and complexity backfire (cub sort prototypes reg-spilling +25-37%, coarse-fine histogram +14-24%). Bottom line: "Scheme X is the Pareto endpoint for B200+DSv3.2" — the direct ancestor of the falsification-history memory.

2.3 The CUDA→cuteDSL port (Q16; planned 15-17 days, done in 2)

  • Trigger: cuTe-DSL radix beat GVR in 2/9 fp32 cells; the user issued a verbatim mandate. One key human correction mid-way: the agent argued "≤5% is infeasible" from prior data and was called out for a category error (algorithm gap + language gap stacked ≠ language gap); the README keeps a full RECONSIDERED section.
  • Decisive consequences: ① the deliverable became the baseline of everything op-bench (gvr_cutedsl); ② the 10-entry cuTe DSL pitfall table became the engineering substrate of fast iteration; ③ the tie-aware exactness criterion was finalized; ④ the JIT compile-cache dropped the iteration cycle from hour-scale rebuilds to minutes.

2.4 Three generations of synthetic data

Q18 uniform (the baseline itself distorted 2.2×) → Q19 distribution fitting (GVR still systematically low — the temporal structure of preIdx was unmodeled) → Q19 Design C temporal coherence (prev_topk=topK(row+c·σ·noise), bisecting c to hit a target hit-rate) → establishing the doctrine that "synth is an upper-bound estimate of the real speedup". Real per-layer captures (Q9j/Q9k) found things synth could never find (the L36 outlier; the single-constant kFTarget 384→512 fix). The single-Beta tail mismatch was left for the op-bench-era unified temporal-synth skill.

Humans wrote the three-layer CLAUDE.md rules (check the excluded-paths ledger before proposing, F006, dual-.so sync rebuilds, dispatcher changes require re-running 4 validation reports); and the explicitly pre-authorized self-decide mode (kept verbatim in SESSION_RESUME: "after each optimization … discard on negative results and move on … make the best call yourself and execute; do not stop to wait for human confirmation"). 3. Era-2 前期: op-bench 基建与 op7-op16(2026-06-10 ~ 07-04)

3.1 Harness 基建的六个决定性设计

  1. 解耦 + perf-parity 门:每个 standalone op 先对 in-tree 生产 op 打 ~3% parity,保证结论可迁移回生产。
  2. cold-L2 + CUDA-graph 计时收敛到单函数 harness/sweep.py::_time_both——所有后续 op 只能 import 或逐字复刻:纪律靠代码路径唯一性维持,不靠规程文字。
  3. nsys 仲裁层:event 计时带 0.76-0.95× graph-launch 偏差;ship 裁决一律 nsys pure-kernel ×3 中位 + anchor 校验(0.94-1.03 才认可本批可比)。
  4. exactness 门 = vdiff=0(sorted value-multiset)+ uniq==K,禁 torch.randn(bf16 塌缩 ~256 值破坏平票语义)。
  5. 可恢复性:jsonl 逐 cell append + done-skip;报告单一 last-writer;新 op 以 anchored ratio-transfer 叠加。
  6. 测量阶梯固化:host replay/clock64 → cold-L2 event → nsys ×3(ship)→ NCU(归因)。升级触发:小 N launch 地板 / event 可疑 win / 任何 ship claim。

4. Era-2 mid: op17→op21, the evolution and shipping of HLS (2026-07-01 ~ 07-08)

4.1 What HLS is

HLS = h-tracked Ladder-Secant: the threshold search formalized — the optimal threshold is the plug-in order statistic of the preIdx gather sample, θ̂≈GS-1(h·K), where the only unknown is the one-dimensional scalar h (effective retention rate); a static multi-threshold ladder is a batched grid search over the unknown h, and both performance cliffs (240µs fallback, slot overflow) are "h falling outside the static bracket". Full HLS = M-ary ladder single-pass counting + log-count regula-falsi fallback + cluster-parallel fallback recount + ĥ-adaptive rung placement (deferred).

4.4 Implications for an autonomous harness

  1. A mandatory ladder of cheap probes: crux → host-replay → microbench → kernel ("20 minutes of host replay killed weeks of wrong-shape kernel work").

  3. "Composing verified primitives" out-produces "inventing new kernels": HLS is a six-source synthesis; op21's sixteen iters contain zero new algorithms.
  4. Measurement-axis discipline: the event axis produced three reproducible lies; paired same-process A/B, anchor re-anchoring, and within-run ratios are the verdict.
  5. The explore→productize switch = residual losses fully attributed to structure; dispatch complexity belongs in the objective.
  6. Schedule one mathematical formalization after an empirical plateau.
  7. Exactness needs adversarial + real-data dual tracks.
  8. Code quality and compile keys are real optimization currency (never-executed fallback code = a systematic 4% tax); resumability is a native harness capability (~1/3 of handoff docs were insurance premiums against node loss — all of them paid out).
