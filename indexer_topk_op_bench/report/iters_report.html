DeepSeek-V4 GVR Top-K — P2 / P4-snap Iteration Counts (BS=1)

Data-dependent convergence-iteration counts of the GVR (Guess-Verify-Refine) heuristic Top-K kernel, swept over seq-len N x dtype x top-K at batch size 1. Counts are replayed in fp32 from the cuteDSL algorithm (harness/count_gvr_iters.py) and validated 108/108 against the real cuteDSL kernel's selected top-K set. Back to main report.

Phases counted

  • P2 (secant search) — refines the candidate threshold so the GE-count lands in [K, kC]. Each iteration is one full block_count_ge pass over N (memory-bound). Capped at 15; done=1 on convergence, done=2 on bracket exhaustion (→ Phase-3 retry-shrink bisection).
  • P3 candidate count — the number of elements ≥ threshold that P3 streams into the shared-memory keys[]/vals[] buffer (capped at kC). The secant in P2 targets kFTarget, so this lands at ~1.4–4× the final K; it is the working-set size P4 then snaps down to exactly K.
  • P4 snap — histogram-bucket k-th selection then a block_fused_snap_iter loop refining the threshold to the exact K-th rank. Operates only on the ≤ kC candidates in shared memory (no global reload). Snap runs only when cand_count > K (branch B); the cand==K / cand<K fast paths report 0.

Method

In-kernel clock64() stamps each phase boundary (subclass GvrTopKKernelTimed; vendored kernel untouched). The clock64 cycle fractions split the production op's cold-L2 wall µs (event-timed, same metric as §1) into P1–P4 — immune to SM boost-clock uncertainty. Phases: P1 preIdx min/max/mean (scans K); P2 secant search (each iter = one full-N block_count_ge, global, memory-bound); P3 candidate collect (one full-N pass, global); P4 histogram + snap (shared-memory candidates only).

Notes

  • P2 converges (done=1) in 100.0% of sampled rows on these realistic temporally-coherent distributions; bracket exhaustion (the Phase-3 retry-shrink fallback) is not exercised here.
  • P2 iters scale with K: mean 512→1.01, 1024→1.41, 2048→2.06. The Phase-1 pre-idx mean is a tighter initial guess at small K, so K=512 almost always converges in 1 secant step; larger K needs 2-3.
  • P2 iters grow mildly with N (more elements widen the count gap the secant must close): at K=1024 fp32, mean rises ~1.0→2.0 across N=4K→256K.
  • P4 snap iters depend on dtype: half-precision ties collapse candidate values into fewer distinct buckets, so bf16 snaps fastest (mean 2.59) while fp32 takes the most (4.29); fp16 is in between (3.62).
  • P3 collects 2.99× K candidates on average (mean 2775, max 5115); the secant targets kFTarget, so the over-collect ratio shrinks with K: 512→3.96×, 1024→3.37×, 2048→1.39×. dtype barely moves it (identical bit-pattern thresholds) except K=2048, where fp32 uses kFTarget=3072 vs 4096 for half-prec.
  • P4 snap is bounded by cand_count but in practice stays small (mean 3.50, p95 7, max 15); unlike P2 it reuses the shared-memory candidate buffer, so each iteration is cheap (no global reload).
  • Counts validated 108/108 against the real cuteDSL kernel (harness/count_gvr_iters.py selected-set check).
  • Phase timing crosses over near N≈32K. Below it P4 (shared-memory candidate snap) dominates (~53% at N≤16K); above it the global-memory full-N scans P2+P3 dominate (~76% at N≥128K). This mirrors the cost model: P2/P3 re-read all N logits from global memory (memory-bound, grows with N) while P4 works only on the ~3×K shared-memory candidates (N-independent).
  • P1 (preIdx min/max/mean over K elements) is N-flat at ~2.5µs, so its share decays from ~15% at small N to ~6% at 256K.
  • dtype shifts total time via P2/P3 byte traffic: at K=1024 mean total is 24.6µs (bf16) < 25.4µs (fp16) < 26.9µs (fp32) — half-precision halves the logits footprint the full-N scans must stream.
