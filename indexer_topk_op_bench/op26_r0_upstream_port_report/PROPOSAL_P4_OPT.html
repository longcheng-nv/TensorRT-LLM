1 · D1 distP4:分布式 P4(cs≥4,最大杠杆)

问题形态:handoff#2 之后,leader 单 CTA 先串行拉取 各 peer 的候选 (值+索引 各 ~kC 条,LD.E 远端逐元素),再在合并缓冲上独自跑完整选择流水线;peers 全程空转陪跑(epilogue barrier 保活)。§9f 证明核心选择成本跨 rung 不变 → cluster P4 的全部增量 = 这段串行机制。

D1a · peer-push gather(第一步,小 diff,先行实验)

设计:方向反转——不让 leader 拉(1 CTA 串行),让每个 peer 在自己 collect 结束后立刻把自己的 (keys, vals) 段 push 到 leader SMEM 的预分配偏移区(st.shared::cluster,写侧需 release 语义:cluster_arrive() 而非 relaxed —— 见 DSMEM 竞态教训)。偏移 = 各 CTA 的 slice 前缀(collect 计数已在 handoff#1 交换过,或加一轮 4 字节计数交换)。leader 只等一个 barrier,gather 段消失。

预期:gather 3.11 µs → ~0.3–0.5 µs(32 线程 × cs 个 CTA 并行写,且与最慢 peer 的收尾天然重叠);peer_wait 部分被吸收(push 完即 arrive)。cs8 kernel ≈ −13–18%,cs4 ≈ −6–9%;全格(cluster 327/865)geomean 估 +5–7%。

风险:① DSMEM 写→读可见性(必须 release+acquire 对;历史上已翻过一次车,330/330 假绿);② 前缀偏移需要早一步可用(计数交换提前到 handoff#1);③ SMEM 容量不变(仍是同一块合并缓冲)。

D1b · 分布式 rank + scatter(全量设计,D1a 之后)

设计:候选根本不搬。① 各 CTA 在本地候选上并行建粗直方图(bin 定义共享:min/max 先做一轮 cluster 归约);② 直方图(512×4B)经 DSMEM 归约合并到 leader(或每 CTA 归约自己负责的 bin 段);③ leader(或 warp0)在合并直方图上找 b*/rank_above,细层同样分布式(各 CTA 只重扫自己的 bin-b* 候选);④ 各 CTA 用「全局 bin 前缀 + 本 CTA 段内前缀」直接把自己的候选 scatter 写到输出 GMEM——rank-scatter 的位置正确性由两级前缀保证,tie 类走既有 exact-tail(罕见,可回退 leader-only)。

预期:再吃掉核心选择的大头(4.8 µs 串行 → 本地扫描 cand/cs + 2–3 个 cluster barrier + 直方图合并);cs8 P4 有望 9.6 → ~4 µs,kernel ≈ −25%;全格 geomean 估 +8–12%(与 D1a 部分重叠,非线性叠加)。

风险/边界:① barrier 数增加(cluster 归约 ×2–3)——P4 恰是 barrier-bound,必须 nsys 净值判定;② min/max 与直方图 bin 参数需先行 cluster 归约(多一轮握手);③ exact-tail/p4tt 在分布式布局下的 tie 收集要重新推导(建议 v1 先回退 leader-only tail);④ op34 教训设界:多 CTA collect-only 的 oracle 上界 ≈ sglang 持平——不要以「反超 sglang」为验收目标。

2 · D2 fine/coarse-search barrier 减负(全 rung,cs=1 主杠杆)

D2a · 搜索段 warp0 化(op35 已点名,§9f 定价)

设计:粗搜索与细搜索的「per-warp 部分和 → barrier → thread0 选 warp → barrier → 目标 warp lane0 串行走」三步结构,每段花 2 个 CTA barrier + 2 段串行走。改为 warp0 单 warp 完成:512/256 个 bin 由 warp0 的 32 lane 每人 8–16 个 bin 做 warp 内反向前缀(shfl 扫描,无 CTA barrier),其余 warp 直接去等下一个必要 barrier。粗+细两段合计省 ~4 个 barrier + 2 段串行走。

预期:coarse-search 0.7–0.84 µs + fine 内搜索部分,估每格 −0.3–0.6 µs → 全格 geomean +3–5%(cs=1 收益最大,cluster 端同样适用)。

风险:低——纯 CTA 内重排,不碰跨 CTA 语义;对照证伪史无冲突(它砍 barrier,不加 pass)。

D2b · 条件跳过细层(先探针,后实现)

设计:当 cnt[b*] ≤ K − rank_above(骑跨 bin 全取)或 cnt[b*] 极小(直接 thread0 精选,类似 p4tt)时,细层的 re-zero+build+search 整段可跳过——省 1.5–1.8 µs 的整个 scan #3。证伪史注明该 fast-path 从未实现。第 0 步是 10 分钟探针:在 gvrpkgp4t 孪生上顺手 dump (cnt[b*], K−rank_above) 的 865 格分布,先量触发频率再决定做不做(触发率 <10% 就放弃)。

注意:这是「砍 pass」类操作,但零协调成本(一个标量比较),不属于被证伪的「加协调换 pass」家族。

3 · D3 p4tt 下探 K<1024(tail 封顶,搭车在途 p4tt 战役)

设计:p4tt(小 tie 类 collect + thread0 精选)当前门 top_k ≥ 1024;K=512 触发 exact-tail 时只能走 4 级 radix 重写 → flash_128k_L42 付 5823 条 tail 指令(26×)、其 P4 的 41.6%。把 p4tt 门降到全 K(tie 类 ≤128 时),K512 的逃逸被封顶。改动量小(门条件 + 既有代码路径),与在途的 p4tt 快路径战役(RESUME_P4TT)同一改动面,应合并执行。

预期:中位无感(tail 中位仅 5–6%),尾部格 +5–40%(当前 2 个 K512 格 >15%,34 个 v32 格 >15% 已走 p4tt);本质是鲁棒性/最差格修复,符合 ship rule 的 worst-cell 约束。

1 · D1 distP4: distribute P4 across cluster CTAs (cs≥4, biggest lever)

Shape of the problem: after handoff #2 the leader serially pulls every peer's candidates (keys+vals, ~kC each, element-wise remote loads), then runs the whole select pipeline alone while peers idle at the epilogue barrier. §9f shows the core select cost is rung-invariant → the entire cluster-side P4 increment is this serial machinery.

D1a · peer-push gather (first experiment, small diff)

Design: invert the direction — each peer, right after its collect, pushes its (keys, vals) chunk into the leader's SMEM at a precomputed prefix offset (st.shared::cluster; writer needs release semantics — cluster_arrive(), not relaxed, per the DSMEM race lesson). Offsets come from the counts already exchanged at handoff #1 (or one extra 4-byte count exchange). The leader waits on one barrier; the gather segment disappears.

Expected: gather 3.11 µs → ~0.3–0.5 µs (32 threads × cs CTAs writing in parallel, naturally overlapped with the slowest peer's tail); part of peer-wait is absorbed. cs8 kernel ≈ −13–18%, cs4 ≈ −6–9%; grid geomean est. +5–7%.

Risks: DSMEM write→read visibility (release+acquire pair; we shipped this bug once before — 330/330 false-green), earlier availability of prefix offsets, no SMEM growth (same merged buffer).

D1b · distributed rank + scatter (full design, after D1a)

Design: never move candidates. ① each CTA builds a local coarse histogram over its own candidates (shared bin params via one cluster min/max reduction); ② histograms (512×4B) merge via DSMEM reduction; ③ b*/rank_above found on the merged histogram (warp0), fine level equally distributed (each CTA rescans only its own bin-b* candidates); ④ each CTA scatters its own candidates straight to output GMEM using global-bin-prefix + per-CTA-segment-prefix — rank contiguity guaranteed by the two-level prefix; ties fall back to leader-only exact-tail in v1.

Expected: also eats the leader-only core select (4.8 µs serial → cand/cs local scans + 2–3 cluster barriers + histogram merge); cs8 P4 9.6 → ~4 µs, kernel ≈ −25%; grid est. +8–12% (overlaps D1a, not additive).

Risks/bounds: extra cluster barriers in a barrier-bound phase (nsys net verdict mandatory); bin-param pre-reduction handshake; distributed tie collection deferred to v1-fallback; and the op34 bound — the multi-CTA collect-only oracle ≈ sglang parity, so "beat sglang" must not be the acceptance bar.

2 · D2 fine/coarse-search barrier diet (all rungs, main cs=1 lever)

D2a · warp0-ized searches (named by op35, now priced by §9f)

Design: both 3-step searches (per-warp partial sums → barrier → thread0 picks warp → barrier → target-warp lane0 serial walk) become a single-warp job: warp0's 32 lanes cover 512/256 bins at 8–16 bins/lane with a warp-local reverse prefix (shfl scan, no CTA barriers). Saves ~4 barriers + 2 serial walks across coarse+fine.

Expected: −0.3–0.6 µs/cell → grid +3–5% (largest at cs=1, applies everywhere). Risk low: CTA-internal only; cuts barriers, adds no pass — no ledger conflict.

D2b · conditional fine-level skip (probe first)

Design: when cnt[b*] ≤ K − rank_above (whole straddling bin taken) or cnt[b*] tiny (thread0 direct select, p4tt-style), skip the fine re-zero+build+search entirely — saves the whole 1.5–1.8 µs scan #3. The ledger notes this fast-path was never implemented. Step 0 is a 10-minute probe: dump (cnt[b*], K−rank_above) across the 865 grid on the gvrpkgp4t twin; drop the idea if trigger rate <10%. This cuts a pass at zero coordination cost (one scalar compare) — not in the falsified add-coordination family.

3 · D3 p4tt below K=1024 (tail cap; merge into the in-flight p4tt campaign)

Design: p4tt currently gates on top_k ≥ 1024; K=512 exact-tail firings run the 4-level radix (flash_128k_L42: 5823 tail inst, 26×, 41.6% of its P4). Lower the gate to all K (tie class ≤128). Small diff on the same surface as the in-flight p4tt fast-path work (RESUME_P4TT) — execute together. Median-invisible (tail med 5–6%), tail cells +5–40%; a worst-cell robustness fix aligned with the ship rule.
