4 · 问题三: 保留 GVR 骨架的进一步优化方案

方案 A (P0 优先): HLS fallback 栈整体移植 — H1+H2+H3+H4

见 §2 表。综合预期 (按 op21 P0 iter15/iter16 已测组合): 65K–262K 段 real 轴 +9–28% (262K 应力 1.24–1.38×), worst/K2048 尾部 1.15→1.44×, 16-bit 全线; N<65536 逐 bit 不变。这是 PR 输赢地图区域③④的直接解, 且全部为已上硅技术的移植, 风险最低。

方案 B (P1 优先, 用户命题展开): block max-pool 投机跳块 — 把 P2/P3 从"全 N 扫描"变成"稀疏扫描"

动机链: P2/P3 是 issue-bound 而非访存-bound (墙②③), 每候选带元素 ~16 inst; 真实 preIdx/top-K 空间上强聚簇 (positional 研究: 真实 seg_frac≈0.24 vs IID 0.52, gather footprint 集中) → 大 N 下绝大多数块不含任何候选, 对它们花 1-cmp/elem 甚至 16-inst/elem 都是纯浪费。跳块 = 把这部分指令整体归零。证伪史查重: 最近亲属是 op29 streaming-HBE (已 ship, 同货币: 削指令) 与 op31 HBE-C (教训: 固定 prepass 税 N<512K 必输 → 必须融合进已有遍, 不许加独立遍); "省流量"表述则会撞墙② —— 本方案全部收益记账在指令侧。

变体机制正确性预期与依据风险
B1 融合块最大值边带P2 ladder 计数遍本来就读全 N —— 顺路为每 tile (512–1024 元素) 记录"tile-max 越过的最高 rung 编号" (u8, 262K/512=512B SMEM)。P3 collect 按选定阈值跳过 rung-class 低于阈值的整 tile (不读不比)精确 — tile-max 是本步真值, 跳过判据保守 (max<thr ⇒ 块内无候选)P3 从全 N 扫描 → 仅候选覆盖块; 真实数据大 N 下候选块占比经验上 ≪ 25% (聚簇性) → P3 期望省 ≥60% 指令; 参照 op29 同货币收益 1.33–1.75×@65K–262KP2 每 tile 增 ~2 inst + 1 SMEM 写; 边带 SMEM 与 P4 hist 复用 (P1b 先例); N-gate ≥65536 (op31 固定税教训)

B3 跨步投机跳块 (真"投机")把上一 decode step 的 tile rung-class 持久化到侧缓冲 (per-layer [nTiles] u8); 本步 P2 先只扫"上步高类 + preIdx 覆盖"的块做 ladder 计数, 计数判据 cnt≥K 通过则 P3 同域收集; 未过 → 全扫兜底 (= 现有 fallback 形态)投机+验证: 计数判据只保证"够 K 个", 不保证跳过块中无更大新值 — 精确性要求兜底触发条件包含 value-level 检查 (选出的第 K 值 ≥ 全局 rung-0 计数所隐含下界), 设计期必须过对抗 gate (op21 iter11 0/72 教训)时间相干性依据: logits AR(1) lag-1 ρ≈0.44–0.47, V-collapse 每 15–18 步 (HLS assumption check) → 期望 ~85% 步投机成功, 失败步价格=一次全扫 (≈现 fallback); 上限 = P2 也变稀疏 (B1 只稀疏 P3)需侧张量 → API/调用面改动 (与 HLS Step 3 同一障碍, 曾因此推迟); V-collapse 全层同步 → 失败步聚簇; 建议列为 B1/B2 落地后的第二梯队, 且先做 host replay 测投机命中率
B 方案落地路径 (iter0 先测不建纪律): ① host replay 用真实捕获统计 tile 候选覆盖率与 rung-class 分布 (预算: 半天, 直接给出 B1 理论上限); ② clock64 相位确认 P3 份额 (仅归因用); ③ B1 kernel (subclass/flag, vendored 不动) → 对抗+真实双轨 gate → nsys ×3 锚定判决; ④ B2 搭车; ⑤ B3 单独立项。判据: worst/real/best 三轴 [见 ship 纪律], 任何单轴 >5% 回退即 N-gate 收紧。

方案 C (P1, 与 B 合流): op29 streaming-HBE 正式移植入 PR 血统

op29 iter12 已在 op-bench ship: 64×64 分块 coalesced 采样 → 单列 A (rank 2×rS_K) → 1-cmp/elem 融合 collect → cnt_a≥K 判据 → miss 回退 stock; 守卫 N≥65536 全 K; 262K 1.62–1.75× / 131K 1.33–1.48× / 65K 1.03–1.13×, 全部在部署包络 (N≤256K) 内。它与 B1 是同一思想的两种粒度 (HBE=采样列消元, B1=块级消元), 建议合流为一个战役: 先移植 HBE (数字已证), B1 作为其上的增量 A/B。注意 op31 的反例边界: cluster 版 HBE-C 在包络内 wash-to-loss — 只移植 op29 的单 CTA streaming 形态。

方案 D (P2, 诚实定界): BS=1 小 N 区域①②

op34 已双重锁死"GVR 骨架在 BS=1 小 N 追平 sglang"整体不可行 (oracle 多 CTA collect-only ≈ 持平, 无 rank 尾部余量)。保骨架下仅存两个未跑杠杆: ① intra-CTA warp 流水线 (证伪史标注"最深未触杠杆", Q3'/Q4' 从未实测 — 占用墙是结构性的, 但单 CTA 内的 ILP/相位重叠没试过); ② launch 微调 (OPT_CAMPAIGN cs4-nt512 ~2.2%)。预期天花板低 (≤10%), 列为机会性任务; 区域①②的战略答案是接受 + 靠正确性叙事 (sglang_v2 条件精确, §8.1) 而非硬追。
