## 0 · 被排除的嫌疑(重放证据)

- **fb_fix 无辜**:全部回退格 fb 进入率 = 0(P2 都在 15 iter 内收敛,
  从未走 done=2 → fallback)。修正版 fallback 的额外成本不在关键路径上。
- **"CCDF 非指数" 不成立**:所有回退格在 [K, kC] 尾窗内 log2(count) 对
  阈值的线性拟合 R² = 0.990-1.000 —— log 域插值的模型假设在**尾部**完全
  成立。问题不在模型,在**用法**(瞄准点 + 迭代格式 + 括号跨度)。

## 1 · 根因(按回退簇)

### R1 — K1024 @131K(两臂、全 dtype,最深 0.56×):瞄准点在接受带边缘

- 语义:接受带 [kK,kCC];op26 log-falsi 瞄准 kFTarget。K1024 的 kFT=1024
  **恰好 = kK = 接受带下边缘**(V4 vendored 表如此,fp32 窄窗也未改)。
- 重放 trace(real 行):anchor 2 趟(469 → **3901∈[1024,5120] 一跳命中**);
  op26 5 趟(469 → 5906 → 851 → 976 → 1056)——精确的 log 插值真的落在
  1024 附近,但 ~一半概率落在 K 之下 ⇒ 被拒 ⇒ 从 undershoot 侧单侧爬行
  (851→976→1056,regula-falsi 端点冻结的线性收敛)。
- **anchor 的"运气"是被调过的**:线性插值在凸的 log-CCDF 上系统性
  overshoot,而 overshoot 方向恰好落进 5 倍宽的 stock 接受带中部
  (vendored 注释"V4's kFTarget=kK alignment"就是为线性插值的偏置调的)。
  log 插值**更准**反而更糟——准星对着边缘,准 = 一半脱靶。
- 窄窗 [1024,2048](fp32)把接受带又压缩 2.5×,放大拒绝率;而每趟 =
  全 N 扫描,131K 时 3 趟额外 ≈ +393K 元素扫描 ⇒ 大 BS 带宽受限下
  passes 5/2 = 2.5×,与实测 0.56-0.62(≈1/1.7-1/1.8,含 P1/P3/P4 常数
  项稀释)吻合。
- 同一机理在 N=8-32K 是**净赢**:+1-3 趟很便宜(N 小),而 cand 从
  3200-4900 压到 ~1100(P3 collect + P4 rank-scatter ∝ cand)⇒ 1.9-2.1×。
  **窄窗是在用 P2 趟数换 P4 候选量,汇率随 N 变化** —— 131K 处汇率倒挂。

### R2 — K2048 16-bit 中段带(0.90-0.955):种子毒化 + 体部凸性 + 端点冻结

- 重放 trace(fp16 65536 best):op26 8 趟,counts 33454→20703→13435→9581
  →7476→6192→5423→4752 —— 比率 ~0.65 的几何爬行。三因叠加:
  1. **hi 端是未实测种子** (pmax, chi=1)(op22 MECH_FINDINGS 的 pmean
     毒化同族):log 插值的分母 log2(clo/1)≈15 巨大 ⇒ f≈0.2 小步;
  2. 初始括号横跨**分布体部**(Gaussian 体,log-CCDF 凸),不在指数尾内
     ⇒ log-falsi 每步都落在 overshoot 侧;
  3. regula-falsi 端点冻结 ⇒ 单侧线性收敛。
  anchor 线性公式 f=(33454−4096)/(33454−1)≈0.88 一跳跨过体部,3-4 趟完成。
- K1024 16-bit @131K 与 fp32 同因(kFT=1024=kK 边缘瞄准,stock 宽窗也救
  不了准星对边缘)。

## 3 · 算法优化方向(按优先级)

- **A(直接修复,V3)**:P2 插值改为"最近两个实测点的 log-secant +
  括号 clamp",瞄准点改 √(kK·kCC);两处均为 P2 标量逻辑小改,不动
  内存路径与精确性防线(接受带判据不变)。预期消灭 R1 主体、大幅缓解 R2。
- **B(种子修复)**:P1 免费顺带实测两端计数——P1 本来就要全行扫一遍建
  直方图/统计(视内核版本),把 count(pmin')/count(pmax') 顺带算出,
  替换 1.25K/1 假种子;R2 的因素 1 归零。与 op22 MECH_FINDINGS 的
  pmean-init 毒化是同一处伤口。
- **C(一趟定界,结构性)**:第一趟 count_ge 升级为 **32/64 桶单趟
  直方图**(值域按 P1 的 [pmin,pmax] 均分或按 log 域分):一趟即得全部
  桶边界计数 ⇒ 直接查表定出跨 [kK,kCC] 的桶,P2 至多再 1-2 趟精修。
  迭代数对分布形状**彻底不敏感**(radix 思想借入 GVR,但保留 GVR 的
  candidate-collect 轻量路径)。预期 P2 趟数 ≤2.5 恒定,同时窄窗可
  无代价全域启用(cand 压缩收益保留)。代价:第一趟每元素多一次
  bucket-index 计算 + smem 原子,带宽近乎不变。
- **D(自适应窗宽,cost-model)**:接受带宽度按趟数/候选量汇率解析设定
  kCC(N) = kK · (1 + c·kK/N 形式),小 N 收窄、大 N 放宽——把"窄窗在
  131K 倒挂"变成连续 cost model 的自然输出,而非 per-cell 查表。
- op26_mc:维持不 ship(cluster P2 已被切片摊薄,上述修复的收益上限
  也被同样摊薄)。
