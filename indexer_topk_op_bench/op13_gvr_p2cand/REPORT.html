GVR snap-P4 内核(gvr_topk_decode.py)相位链: P1 preIdx 统计 → P2 secant 阈值搜索(每次 eval = 一次 full-N count_ge 扫描)→ P3 候选收集 → P4 直方图 + snap。iter0–7 已证明:

0. One-line conclusion

The linear interpolation in the GVR decode top-K kernel's P2 threshold search is the root cause of eval-count inflation at large N / narrow candidate windows. Replacing it with log-count-space interpolation f = log2(clo/kFT) / log2(clo/chi) (stateless, single-formula change) flattens the P2 full-N scan count in every regime (host replay), passed 396/396 kernel exactness, and per the nsys ×3-median A/B ships N-dispatched for K1024 (V4 Pro, first time: 8K −32.1%, 131K −22.0%) and for K2048 at all N (large N −12%); K512 keeps the iter7 lin-narrow ship unchanged (log variants lose to it there).

1. Background & goal

The GVR snap-P4 kernel (gvr_topk_decode.py) phase chain: P1 preIdx stats → P2 secant threshold search (each eval = one full-N count_ge scan) → P3 collect → P4 histogram + snap. Established in iters 0–7:

  • snap-P4 is candidate-count-bound (corrects op12's rank-scatter-P4 conclusion);
  • Narrowing kCC cuts P4 but the P2 eval tax eats most of the gain; with eval-optimal kFTarget the tax drops to +1 eval and K512 fp32 nets −5~15% at N≤65K (shipped in iter7 as _NARROW_TABLE={(fp32,512):(1536,1280)});
  • Large N≥131K always lost (each eval 8–12µs) ⇒ mandatory N-dispatch; K1024 rejected after ×3-median exposed real regressions (+15.8% @4K).

iter8 goal (the only live lever after op20 closed): a cheaper P2 root-finder — capture the narrow-window P4 saving without extra full-N scans, and try to flip large N.

2. iter8a — root cause & host-replay A/B done

Root cause: the count-vs-threshold curve (CCDF tail) is ~exponential while the baseline interpolates linearly in value space (f=(clo−kFT)/(clo−chi)) ⇒ systematic under-stepping. An exponential tail means log(count) is ~linear in the threshold ⇒ interpolating in log-count space should land in one step.

Method: p2_replay.py (validated 720/720 vs the real kernel) + interp_mode ∈ {linear, logcount, illinois, logillinois}; rootfinder_sweep.py sweeps kFTarget per (window, mode), eval-optimal pick, hard gate = 100% exact + converged over 3 beta cfgs × 4 seeds × all N.

2.2 Key readings

  • Narrow-window large-N eval inflation eliminated: K512 kc2x @262K: 3.75 → 3.00 evals (tax +1.75 → +1.0); K1024 kc2x @262K: 3.83 → 3.00.
  • Base-window large-N free win: K1024 @131K 3.50→2.75 evals AND cand 2.9→2.0×K; K2048 @262K 3.75→3.00 (−0.75 full-N scans) AND cand 1.13→1.07×K.
  • Illinois falsified: bit-identical to linear (initial brackets are fake counts; the secant rarely hits the same side twice, so stale-endpoint scaling never triggers); logillinois ≡ logcount ⇒ the stateless log formula captures all the win.
  • dtype-invariant (P2 always computes in fp32): bf16/fp16 sweeps match fp32; 16-bit K2048 base window cand 1.16–2.22×K → 1.06–1.10×K at unchanged evals ⇒ a uniform per-K ship table, no dtype branch.
