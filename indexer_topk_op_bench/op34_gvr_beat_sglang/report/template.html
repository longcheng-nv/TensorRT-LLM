1 · Objective & setup / 目标与设置

2 · Real data — distribution & hit-rate / 真实数据——分布与命中率

The captured indexer logits are near-exponential (CCDF), so any threshold interpolation lives in log space. The prev-topK hint hit-rate (fraction of the previous decode step's top-K still in the current top-K) varies strongly by model, layer and ISL:

  • pro (K=1024): hit-rate ≈ 0.51–1.00 (high; 1.00 at the degenerate 4K rung where N≈K).
  • flash (K=512): hit-rate ≈ 0.36–0.75 (lower, more volatile across layers).
  • The top-K selection boundary is razor-thin — the relative gap between the K-th and (K+1)-th value is ~1e-5, so exactness must be tie-aware.

Consequence for a threshold kernel: a weak hint (low hit-rate) forces a low, safe threshold that admits a huge candidate set (up to the whole row). Only a strong hint yields a small candidate set — and even then not small enough (see §5).

采集到的 indexer logits 的 CCDF 近似指数分布，因此任何阈值插值都必须在对数空间进行。上一步 top-K 的 hint 命中率（上一解码步 top-K 中仍留在当前 top-K 的比例）随模型、层、ISL 显著变化：

  • pro（K=1024）：命中率 ≈ 0.51–1.00（较高；在 N≈K 的退化 4K 档为 1.00）。
  • flash（K=512）：命中率 ≈ 0.36–0.75（较低，跨层波动更大）。
  • top-K 选择边界极其纤薄——第 K 与第 K+1 个值的相对间隔约 1e-5，因此精确性必须 tie 感知。

对阈值核的影响：弱 hint（低命中率）迫使阈值取低而安全，从而收进庞大的候选集（最多整行）； 只有强 hint 才能给出小候选集——而即便如此也仍不够小（见第 5 章）。

3 · Why sglang wins — the NCU CRUX / sglang 为何取胜——NCU 关键实验

Profiling op26_r0auto vs sglang at pro/256k (N=65539) with ncu --cache-control all (cold) is decisive:

  • Both read the row exactly once from HBM (~360 KB ≈ 1× the row). Pass count is not the differentiator under cold-L2 (sglang's 2nd pass and GVR's collect pass are both L2-hot).
  • Both sit at <0.2% of DRAM peak and <1% of SM peak — neither is bandwidth- nor compute-bound. The kernels are latency-bound.
  • sglang's only structural edge: grid (1,8,1) = 8 cooperating CTAs vs op26's (1,1,1) = 1 CTA. 8× the memory-level parallelism (MLP) to hide latency — 1.54× faster for 8× the SMs.

So the lever is MLP, not bandwidth. At BS=1, 147 of 148 SMs are idle, and sglang fixes its cluster at 8 CTAs — suggesting a GVR with C>8 could get more MLP. That hypothesis (§4) is genuine, and is what this campaign built and measured.

在 pro/256k（N=65539）上用 ncu --cache-control all（冷）对比 op26_r0auto 与 sglang 是决定性的：

  • 两者都恰好一次从 HBM 读取该行（~360 KB ≈ 1× 行）。冷 L2 下遍数不是区分点 （sglang 的第二遍与 GVR 的收集遍都命中 L2）。
  • 两者都处于 DRAM 峰值 <0.2%、SM 峰值 <1%——既非带宽受限也非计算受限。核是延迟受限的。
  • sglang 唯一的结构性优势：网格 (1,8,1) = 8 个协作 CTA，而 op26 是 (1,1,1) = 1 个 CTA。 8× 的内存级并行（MLP）用来掩盖延迟——用 8× 的 SM 换来 1.54× 的加速。

因此杠杆是 MLP 而非带宽。BS=1 时 148 个 SM 中有 147 个空闲，而 sglang 把 cluster 固定为 8 个 CTA——这暗示 C>8 的 GVR 或许能取得更多 MLP。这个假设（第 4 章）是真实的，也是本战役实际构建并测量的。

4 · The winning hypothesis — multi-CTA single-pass GVR / 制胜假设——多 CTA 单遍 GVR

Split the row across C>8 CTAs; each CTA does ONE fused count+collect pass at the GVR hint threshold (the hint lets GVR collect at a known threshold where sglang needs a separate histogram pass). A scan-scaling microbench confirms the scan keeps speeding up well past C=8 (N=262144: C8→C64 = 34.6→9.3 µs = 3.7×). So the idea is not a priori dead — the open question was the cost of the collect + the cross-CTA rank tail.

把该行切分到 C>8 个 CTA；每个 CTA 在 GVR hint 阈值处做一遍融合的 计数+收集（hint 让 GVR 能在已知 阈值处收集，而 sglang 需要单独一遍直方图）。扫描伸缩性微基准确认扫描在 C=8 之后仍持续加速 （N=262144：C8→C64 = 34.6→9.3 µs = 3.7×）。因此该想法并非先验死路——悬而未决的是收集成本 以及跨 CTA 的排名尾段成本。

5 · The decisive decomposition — the double lock / 决定性拆解——双重锁

Under real nsys (not NCU, which inflates absolute µs by replay), sglang's full kernel is only 12–19 µs at large N. We decompose the multi-CTA kernel against it. col_oracle = fused scan+collect at the oracle threshold (t = true K-th value → minimal candidates), C=64, without the rank tail — the theoretical upper bound of the GVR scan+collect.

在真实 nsys 下（而非会因回放放大绝对 µs 的 NCU），sglang 整个核在大 N 处仅 12–19 µs。我们据此 拆解多 CTA 核。col_oracle = 在预言阈值处（t = 真实第 K 个值 → 最小候选集）、C=64、 且不含排名尾段的融合 扫描+收集——即 GVR 扫描+收集的理论上界。

Lock 1 (upper bound): col_oracle (16–17 µs @1024k, 12 µs @256k) ≈ sglang's ENTIRE kernel. The best a GVR scan+collect can ever do — given the impossible oracle threshold, maximum parallelism, and skipping the tail — merely matches sglang. The mandatory exact rank of the M candidates is a nonzero extra phase, so GVR_total = collect + rank > sglang. Even a zero-cost rank yields parity, never sglang/1.30.

Lock 2 (relaxed controls, all fail): oracle-full (col+tail) = 2.7–4.0× sglang; real-hint op34_mcta = 4–8×; op26_r0auto (2-pass) = %%GR0%%× grand. Three independent relaxations, none at +30%.

Root cause: cold-L2 both do one HBM read (latency-bound); sglang's saved histogram pass is L2-hot (cheap), while GVR pays for (a) a hint threshold that can't be exact-safe AND tight without a measurement pass, and (b) SEPARATE collect and rank barrier-bound phases that sglang fuses into one lean kernel at the cost GVR needs for collect alone.

锁 1（上界）：col_oracle（1024k 处 16–17 µs、256k 处 12 µs）≈ sglang 的整个核。GVR 扫描+收集所能达到的最好情形——在不可能的预言阈值、最大并行、且跳过尾段的条件下——也仅仅追平 sglang。 对 M 个候选的必需精确排名是一个非零的额外阶段，故 GVR_总 = 收集 + 排名 > sglang。即便排名零成本也只是 持平，永远达不到 sglang/1.30。

锁 2（放宽约束的对照，全部失败）：预言-完整（收集+尾段）= 2.7–4.0× sglang；真实 hint 的 op34_mcta = 4–8×；op26_r0auto（两遍）总均值 = %%GR0%%×。三个独立放宽，无一达到 +30%。

根因：冷 L2 下两者都只做一次 HBM 读（延迟受限）；sglang 省下的直方图遍是命中 L2 的（便宜）， 而 GVR 却要付出：(a) 一个既要精确安全又要足够紧、却离不开测量遍的 hint 阈值；(b) 把收集与排名拆成两个 受屏障限制的阶段，而 sglang 只用一个精简核就把二者融合——其成本恰等于 GVR 单收集所需。

7 · Conclusion & recommendation / 结论与建议

Keep sglang_v2 as the production BS=1 top-K. Beating it by 30% within the GVR threshold skeleton is double-locked infeasible on real V4 decode data: the skeleton's collect phase alone, at its theoretical best, already equals sglang's whole kernel. The GVR family's value lies elsewhere — batched BS>1 throughput, where multi-row saturation changes the MLP calculus (out of this campaign's BS=1 scope). This is a productive falsification: it retires the "multi-CTA + hint single-pass" idea with a measured upper bound, not a guess.

生产环境的 BS=1 top-K 继续使用 sglang_v2。在真实 V4 解码数据上，于 GVR 阈值骨架内 把它击败 30% 已被双重锁定为不可行：骨架的收集阶段在其理论最优下就已等于 sglang 的整个核。GVR 家族的价值 在别处——批量 BS>1 吞吐，此时多行饱和会改变 MLP 的算式（超出本战役 BS=1 范围）。这是一次富有成效的证伪： 它用一个测量得到的上界（而非猜测）为“多 CTA + hint 单遍”这一想法画上句号。
