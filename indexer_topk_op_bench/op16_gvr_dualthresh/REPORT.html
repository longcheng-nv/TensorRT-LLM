1. 目标与约束1. Goal & Constraints

  • 目标：以 GVR-rs 为起点，在报告合成数据上使 >95% case 超越 Radix-cuteDSL 与 SGLang，且各 seq_len 平均加速比高出两者最高值 40%。Goal: starting from GVR-rs, make >95% of report cases beat Radix-cuteDSL and SGLang, with per-seqlen avg speedup 40% above the best of the two.
  • 硬约束（用户）：必须基于 P2 secant method（或其优化形式）——"先 secant 迭代定界，再 refine"，不得替换 secant。Hard constraint (user): must stay within the P2 secant method (or optimized forms) — "secant-bracket then refine"; do NOT replace secant.
  • 双阈值算法 A（用户澄清）：在同一次 secant 中同步得到 threshold_1（count<K，确定赢家），path 可为①单 CTA 复用迭代路径中间阈值，或②双 CTA 并行搜 threshold_1。Two-threshold algo-A (clarified): obtain threshold_1 (count<K, definite winners) within the SAME secant run — via (1) single-CTA reusing path thresholds, or (2) a 2nd CTA in parallel.
  • 计量：所有性能结论用报告口径 nsys 纯内核冷 L2（512MB evict + eager + NVTX 范围内 sync + nvtx_kern_sum，×3 中位）。Metric: all perf claims use the report protocol — nsys pure-kernel cold-L2 (512MB evict + eager + in-range sync + nvtx_kern_sum, ×3 median).

2. 结论摘要2. Executive Summary

结论 ">95% case 超 Radix 40%" 在此 régime（N≤262144，输入完全放入 L2）结构性不可达——与本仓库 op10–op15 反复得到的物理地板一致。verdict ">95% cases beat Radix by 40%" is structurally unreachable in this regime (N≤262144, input fits L2) — consistent with the op10–op15 physical floor.

  • 小 N：Radix 地板 (6.5µs) 低于 GVR 内核地板 (~9µs)；Small N: Radix floor (6.5µs) is below GVR's kernel floor (~9µs);
  • 大 N：GVR 仅 P3 全 N collect 就 ~17µs @262K ≈ Radix flat 总时 ~19µs；阈值-流式算法无法追平 flat radix-select。Large N: GVR's P3 full-N collect alone is ~17µs @262K ≈ Radix's flat ~19µs total; a threshold-streaming kernel cannot match flat radix-select.
  • secant 框架内最优（Scheme X）经 nsys 实测证伪 host 预估：免费 threshold_1 peel + band rank-scatter 精确无回归（flag off byte-identical），但开 flag 后完整 9 配置 K×dtype 网格 X/rs ∈ 0.845–1.022，仅 1 个 cell（K2048 fp32@32K）超 1.0，其余全 <1（host 预估的 K2048 −18% 被 phase4_partition 开销吃掉）⇒ NO-SHIP，HEAD 停在 baseline。Best within secant (Scheme X) — host projection falsified by nsys: free threshold_1 peel + band rank-scatter is exact & no-regression (flag-off byte-identical), but with the flag ON the full 9-config K×dtype grid gives X/rs ∈ 0.845–1.022 — only 1 cell (K2048 fp32@32K) exceeds 1.0, all others <1 (the host-projected K2048 −18% is eaten by phase4_partition overhead) ⇒ NO-SHIP, HEAD stays at baseline.

4. 瓶颈分析4. Bottleneck analysis

  • 相位占比（rank-scatter，K512 fp32）：小 N 时 P4 占 48–64%，大 N 时降到 24%、P2+P3 全 N 流式占 60–70%。Phase split (rank-scatter, K512 fp32): P4 is 48–64% at small N, drops to 24% at large N where P2+P3 full-N streaming dominate (60–70%).
  • P4 是 count-sensitive（非纯 floor-bound）：塌缩点在 cand≈1–2K（K1024：cand 4K→1K ⇒ P4 9963→271 周期；K2048：2K→0.5K ⇒ 10184→576）。P4 is count-sensitive (not pure floor-bound): collapse point cand≈1–2K (K1024: cand 4K→1K ⇒ P4 9963→271 cyc; K2048: 2K→0.5K ⇒ 10184→576).
  • 但收紧阈值以塌缩 P4 会引爆 P2（tax）：K1024 kC=1024 时 P2 11085→44760 周期。But tightening the threshold to collapse P4 explodes P2 (tax): K1024 kC=1024 ⇒ P2 11085→44760 cyc.
  • L2 陷阱（决定性）：B300 上输入 ≤1MB ≪ L2 126MB，重复 count_ge pass 是 L2 命中、廉价 ⇒ "减少 pass 数"类优化无效。真正杠杆是 P4/launch floor。L2 trap (decisive): on B300 the input ≤1MB ≪ 126MB L2, so repeated count_ge passes are L2 hits (cheap) ⇒ "reduce #passes" optimizations are moot. The real levers are the P4/launch floor.

5. 双阈值算法细节（流程图 + 伪代码）5. Two-threshold algorithm details (flowchart + pseudocode)

"双阈值"指在 GVR 的 P2 secant 中同时确定两个阈值：主阈值 threshold（使候选数 M0∈[K,kCC]）与 threshold_1（count M<K，这 M 个是确定的 top-K 赢家）。P4 只需在窄带 [threshold, threshold_1) 上精挑剩余 K−M 个。共尝试过两种变体："Two-threshold" means the P2 secant pins two thresholds at once: the main threshold (candidate count M0∈[K,kCC]) and threshold_1 (count M<K — those M are definite top-K winners). P4 then only refines the narrow band [threshold, threshold_1) for the remaining K−M. Two variants were tried:

  • 变体 0 — band-shrink（iter 0，已证伪）：主动收紧 threshold 使 band 足够小，P4 用廉价单-warp select。Variant 0 — band-shrink (iter 0, falsified): actively tighten threshold so the band is small enough for a cheap single-warp select in P4.
  • Scheme X — free threshold_1 peel（iter 4–5，已实现·精确·净中性）：不收紧阈值；threshold_1 免费取自 secant 迭代路径上"count<K 的最大阈值"（这些点 secant 已经算过，零额外 pass）。Scheme X — free threshold_1 peel (iter 4–5, built · exact · net-neutral): do NOT tighten the threshold; threshold_1 is taken for FREE as the "largest path threshold with count<K" that the secant already evaluated (zero extra pass).

5b. Scheme X 伪代码 — P2 secant 免费记录 threshold_15b. Scheme X pseudocode — P2 secant recording threshold_1 for free

# state: threshold (thr), bracket (val_lo/val_hi, cnt_lo/cnt_hi)
#        dual: thr1 = -inf , M = 0
thr   = pmean                              # P1 seed
count = block_count_ge(row, N, thr)        # 1st full-N pass
thr1  = NEG_FLT_MAX ;  M = 0               # dual-thresh slots (s_thr[3], s_iscalars[5])

it = 0
while it < MAX_REFINE_ITERS and not done:
    if K <= count <= kCC:                   # converged: M0 = count candidates
        done = 1 ; break
    elif count > kCC:                       # too many -> search HIGHER
        val_lo, cnt_lo = thr, count
    else:                                  # count < K -> search LOWER
        val_hi, cnt_hi = thr, count
        if count > M:                       # *** FREE dual hook ***
            thr1, M = thr, count           #   largest count<K threshold so far
    # secant interpolation toward kFTarget (optional inverse-quadratic on last 3 pts)
    f   = clamp((cnt_lo - kFTarget) / (cnt_lo - cnt_hi), 0.05, 0.95)
    thr = clamp(val_lo + (val_hi - val_lo) * f, val_lo, val_hi)
    count = block_count_ge(row, N, thr)    # next full-N pass
    it += 1
# result: threshold=thr (M0 candidates in [K,kCC]) ; threshold_1=thr1 (M<K definite winners)

"免费"的含义：threshold_1 是 secant 迭代已经评估过的某个 count<K 的点，只是把它记下来 —— 不增加任何 count_ge full-N pass，因此对 P2 零 tax。这与变体 0 的"主动收紧阈值"根本不同。"Free" = threshold_1 is a count<K point the secant already evaluated; we merely record it — no extra count_ge full-N pass, so zero P2 tax. This is fundamentally different from variant 0's "actively tighten the threshold".

5c. Scheme X 伪代码 — P4 dual dispatch + partition5c. Scheme X pseudocode — P4 dual dispatch + partition

def phase4_dual(smem_keys, smem_vals, ..., M0):
    if M > 0:
        band_cnt = phase4_partition(smem_keys, thr1, M)   # split M0 by threshold_1
        rank_scatter(smem_keys[0:band_cnt], target_k = K - M) -> output[0:K-M]
    else:                                                 # no free winners -> plain P4
        rank_scatter(smem_keys[0:M0],       target_k = K) -> output[0:K]

def phase4_partition(smem_keys, thr1, M):                 # register-staged, 1 pass over M0
    win_base = K - M                                      # winners fill output[K-M : K]
    frag_v, frag_i = load smem_keys/vals at (tid, tid+T, tid+2T, ...)   # stage to regs
    barrier                                               # avoid RAW on smem below
    band_cnt = win_cnt = 0                                # smem_wcnt[0], smem_wcnt[1]
    for (v, idx) in this thread's staged frags:
        if v >= thr1:                                     # definite winner
            ws = atomicAdd(&win_cnt, 1)
            output_indices[win_base + ws] = idx           # -> output tail [K-M, K)
        else:                                             # band candidate
            bs = atomicAdd(&band_cnt, 1)
            smem_keys[bs] = v ; smem_vals[bs] = idx        # compact band to front
    barrier
    return band_cnt                                       # = new cand_count for band P4

为何净中性（iter 6 nsys）：free-peel 确实把 band 缩小、逼近 P4 塌缩点，但 phase4_partition 的开销吃掉了收益 —— 对 M0 个元素的寄存器暂存 + 2 遍、以及 2 个 smem 计数器上 ~M0 线程的原子槽位竞争。K2048（band/M0 小）净中性 0.95–1.02×，K512（band 大）全 N 净亏 0.86–0.98×（实测，见 §7d）。仅存未试改进：warp 聚合原子的更廉价 partition —— 但即便如此也只可能救 K2048 大 N，救不了 K512（大 band 即便 partition 免费，P4 也几乎不塌缩）。Why net-neutral (iter 6 nsys): free-peel does shrink the band toward the P4 collapse point, but phase4_partition's overhead eats the gain — a register-staged 2-pass over M0 elements plus smem-atomic slot contention on 2 counters across ~M0 threads. K2048 (small band/M0) net-neutral 0.95–1.02×; K512 (large band) is a net LOSS at every N, 0.86–0.98× (measured, see §7d). Only untried refinement — a cheaper warp-aggregated-atomic partition — could at best help K2048 large-N; it cannot fix K512 (a large band barely collapses P4 even with a free partition).

5d. 变体 0 — band-shrink（已证伪的原始双阈值形式）5d. Variant 0 — band-shrink (the falsified original two-threshold form)

最初的双阈值设想是主动收紧 threshold（即降低 kC/收紧 kFTarget），让 band = M0 − c_hi 足够小（≤256），P4 换成廉价单-warp select。代数上：band ≥ M0 − K 且 c_hi < K，要 band ≤ 256 必须 M0 ≈ K，即阈值钉得极紧。The original two-threshold idea was to actively tighten threshold (lower kC / tighten kFTarget) so band = M0 − c_hi is small enough (≤256) for a cheap single-warp select. Algebraically: band ≥ M0 − K and c_hi < K, so band ≤ 256 forces M0 ≈ K — the threshold must be pinned very tight.

  tighten threshold  =====================================>  band shrinks (good for P4)
                      \                                   /
                       \  each tightening needs MORE       (P4 cost drops ~15% only,
                        \ full-N count_ge passes            floor-bound until cand->K)
                         v
             P2 passes EXPLODE 1.3 - 2.5x   <== the TAX
             ---------------------------------------------------------------
             net:  small/mid N = WASH (tax ~= P4 saving)
                   N >= 65536  = LOSS  (tax > P4 saving)          [FALSIFIED]

iter 0 实测（K512 fp32，clock64 周期）：收紧到 kC=1024 时 P2 65536 从 11030→15999 周期（+45%），而 P4 仅 8656→6972（−20%）⇒ 大 N 净亏。即便假设 band-select P4 完全免费，天花板也只有 −27%@4K、−11%@16K、≈0@65K、≥131K 亏 —— 且小 N 仍输给 Radix 地板（6.5µs < GVR 9µs）。这正是 Scheme X 改用"免费"记录、拒绝收紧的原因。iter 0 measured (K512 fp32, clock64 cycles): tightening to kC=1024 pushed P2 @65536 from 11030→15999 cyc (+45%) while P4 only 8656→6972 (−20%) ⇒ net loss at large N. Even assuming a completely free band-select P4, the ceiling is only −27%@4K, −11%@16K, ≈0@65K, loss @≥131K — and small N still loses to the Radix floor (6.5µs < GVR 9µs). This is exactly why Scheme X switched to "free" recording and refuses to tighten.
