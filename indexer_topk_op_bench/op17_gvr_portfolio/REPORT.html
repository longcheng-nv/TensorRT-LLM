1 · Goal & honest scope1 · 目标与诚实定位

Start from the single-CTA GVR (cuteDSL) op and improve per-(seqlen,BS) performance while keeping the GVR structure (preIdx → threshold search → refine) and absorbing the multi-CTA idea. The original ask — +40% average across all seqlen/BS with no regression — was shown to be physically out of reach for this kernel family (P2 already ~1 pass at K512; P3 full-N-read-bound; single-CTA at 1/148 HBM BW). This report delivers the achievable target: a real, exact, no-regression, all-dtype speedup over the single-CTA baseline, largest in the low-BS / long-context decode regime that DSv4 actually runs. 以单-CTA GVR(cuteDSL)算子为起点,在保持 GVR 结构(preIdx → 阈值搜索 → refine)、吸收 multi-CTA 思想的前提下提升各 (seqlen,BS) 性能。原始目标——各 seqlen/BS 平均 +40% 且无回退——已论证对该核族物理不可达(K512 的 P2 已是 ~1 趟;P3 受全-N 读约束;单-CTA 仅 1/148 HBM 带宽)。本报告交付可达目标:对单-CTA baseline 真实、exact、无回退、覆盖全 dtype 的加速,在 DSv4 实际运行的低-BS / 长上下文 decode 区间最显著。

3 · Current best design3 · 当前最优方案

src/gvr_portfolio_cluster_op.py — one cluster of G CTAs per row:每行一个 G-CTA cluster:

P1  each CTA computes band [pmin,pmax] from preIdx (redundant, cheap)
    thr_r = pmin + rank*(pmax-pmin)/(G-1)
P2  each CTA runs ONE block_count_ge over FULL N at thr_r
    -> fills ITS OWN smem_ptcnt + count_r     (free: G redundant scans ~= 1 pass)
    DSMEM-share counts (mapa.shared::cluster + cluster_arrive/wait)
    pick best_r = highest rank with count_r >= K   (tightest)
P3  WINNER (rank==best_r) already holds smem_ptcnt at thr* -> collect, NO recount
P4  WINNER snaps exact top-K from the TIGHT candidate set (small P4); others exit

Why it wins: the sweep replaces P2 (zero extra pass); the winning CTA reuses the exact per-thread count cache its own pass produced; a tighter threshold ⇒ fewer candidates ⇒ smaller candidate-linear P4. band=[pmin,pmax] because all K preIdx ≥ pmin ⇒ count(pmin)≥K ⇔ v_K≥pmin, so it always brackets the K-th value. 为什么赢:sweep 替换了 P2(零额外 pass);获胜 CTA 复用自己那趟已算好的 per-thread count 缓存;更紧的阈值 ⇒ 更少候选 ⇒ 更小的(随 cand 线性的)P4。band 取 [pmin,pmax] 是因为所有 K 个 preIdx ≥ pmin ⇒ count(pmin)≥K ⇔ v_K≥pmin,故必然括住第 K 大值。

Dispatch pick_G: G∈{16,8,4} with bs·G ≤ NUM_SMS/2; else G=1 → single-CTA baseline. Never emits G=2 (unstable). 5 · Verdict5 · 结论

A shippable, exact, no-regression Top-K operator that beats the single-CTA GVR baseline broadly — BS=1 pure-kernel 1.21–1.67×, all three dtypes, up to +48% at K2048/262K. It confirms the multi-CTA multi-threshold portfolio direction. It does not reach the original +40%-universal target (physically unreachable here), and it cedes the very-large-N regime to the existing PR#15198 cluster; a per-(N,BS) dispatch combines the two with no regression. 一个可落地、exact、无回退的 Top-K 算子,宽区间超越单-CTA GVR baseline——BS=1 纯核 1.21–1.67×,三种 dtype 全覆盖,K2048/262K 最高 +48%。它验证了多-CTA 多阈值 portfolio 方向。它没有达到原始 +40% 全区间目标(此处物理不可达),且把超大 N 区间让给现有 PR#15198 cluster;按 (N,BS) dispatch 可将两者组合且无回退。

6 · Remaining optional deep-dives (future directions)6 · 剩余可选深化(后续优化方向)

D1 · Partition + portfolio fusion (highest value)D1 · 分片 + portfolio 融合(价值最高)

Today each CTA scans the FULL N (redundant); at N≥262K the single-winner full-N collect loses to multicta's partitioned scan. Fusion: split the cluster into P partition-groups × T threshold-slots (G=P·T). Each group scans N/P (bandwidth-parallel, like multicta) while the T slots within a group cover distinct thresholds; DSMEM-reduce counts across the P×T grid. This should reclaim N≥262K (multicta's scan speed) AND keep the tight-cand P4 win — potentially beating both baselines everywhere. Cost: a 2-D DSMEM reduction + partitioned collect on the winner group. 当前每个 CTA 扫全 N(冗余);N≥262K 时单-winner 的全-N collect 输给 multicta 的分片扫描。融合:把 cluster 拆成 P 个分片组 × T 个阈值槽(G=P·T)。每组扫 N/P(带宽并行,像 multicta),组内 T 槽覆盖不同阈值;在 P×T 网格上做 DSMEM 归约。这应能夺回 N≥262K(multicta 的扫描速度)且保留紧-cand 的 P4 收益——有望在所有区间同时超越两个 baseline。代价:二维 DSMEM 归约 + 获胜组上的分片 collect。

D2 · Adaptive band from a coarse first passD2 · 由粗扫自适应确定 band

Instead of a fixed [pmin,pmax], let the first (free) sweep also return a coarse CCDF and concentrate the G thresholds where count crosses K on the next launch (or via a 2-level in-kernel refine on the winning slot). Tighter cand at the same G ⇒ larger P4 shrink, especially at small N where cand headroom is limited. 不用固定 [pmin,pmax],让第一趟(免费)sweep 顺带返回粗 CCDF,在下一次(或核内对获胜槽做 2 级 refine)把 G 个阈值集中到 count 跨越 K 的区间。同 G 下更紧的 cand ⇒ 更大的 P4 缩减,尤其在小 N(cand 余量有限)时。

D3 · G-2 cluster stability + larger GD3 · G=2 cluster 稳定性 + 更大 G

Diagnose the G=2 "unspecified launch failure" (smem/occupancy vs launch API) to open the BS=32–64 band to a small cluster; and try G>16 via the non-portable-cluster-size opt-in for finer resolution at BS=1. 诊断 G=2 的 "unspecified launch failure"(smem/占用率 vs launch API),以便把 BS=32–64 带打开给小 cluster;并通过 non-portable-cluster-size opt-in 尝试 G>16,在 BS=1 获得更细分辨率。

D4 · ProductionizationD4 · 产品化

Register as a report op column; full-grid ×3-median nsys; wire into the torch.ops.trtllm.indexer_topk_decode path behind an (N,BS,dtype) dispatch; GSM8K accuracy gate on real DSv4 data (exactness is proven on synth, but validate the tie-boundary on quantized inputs). 注册为 report 算子列;全网格 ×3-median nsys;在 (N,BS,dtype) dispatch 下接入 torch.ops.trtllm.indexer_topk_decode 生产路径;在真实 DSv4 数据上做 GSM8K 精度门(合成数据已证 exact,但需在量化输入上验证 tie 边界)。
