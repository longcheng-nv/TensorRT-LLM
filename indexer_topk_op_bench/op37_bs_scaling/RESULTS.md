## 机理与结论

1. **champion 是严格的 BS=1 latency specialist**(与 R3 compB 结论一致): 每次
   launch 用满整卡(16-CTA cluster / 1024-thread 单 CTA), 顺序 launch 使总时间
   随 BS 线性增长(µs/行 @BS1024 ≈ BS=1 单行时间, 无任何摊销)。head 的批量
   launch 在 BS≤128 近乎免费(SM 未饱和, 行间并行), 直到 BS≥256 才开始线性化,
   因此曲线一边平一边线性, 交叉点必然出现在极小 BS。
2. **BS=1 全胜**: 1.137–2.283×, 9/9 格, 与 b200-027 的 865 格判决 (gm 1.6315)
   跨节点方向一致(本判决两臂同卡配对, 自洽)。
3. **交叉点**: 8/9 格在 **BS=2** 即落后于 head; 唯一例外 pro_1024k
   (K=1024, N=262127, head 单行本身最贵)在 BS=2 仍胜 1.177×, BS=4 交叉。
4. **BS≥16 后 champion 慢一个数量级以上**(0.09–0.18×), BS=1024 慢 25–170×。

## 生产 dispatch 建议(BS 门限)

- **champion 只在 `BS == 1` 时派发; BS ≥ 2 一律走 head 批量臂。**
  这是结构性门(单行契约 + 全卡/launch), 不是可调参数; 与 kf_campaign
  R3_LEDGER 的 "BS==1 gate is structural remedy" 结论一致。
- pro_1024k 的 BS=2 胜出 (1.177×) 是唯一可放宽点(K=1024 且 N≥262K 时
  BS≤2), 但收益窄、增加派发面, 不建议纳入首版; 若未来 envelope 显示
  decode BS=2 高频出现可再评估。
- 若要扩大胜区到 BS>1, 需要 kernel 侧批处理改造(grid.y 批量 / row-team
  co-residency, 参见 compB `kf_bs_scaling/ext/` 已验证方向), 超出本任务范围。
