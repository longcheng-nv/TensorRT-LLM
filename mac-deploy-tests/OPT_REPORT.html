1. Roofline for an SSD-streamed MoE1. SSD 流式 MoE 的 Roofline

The model (552B backbone + 196B Engram) cannot reside in 48 GB at any quantization. The converted checkpoint keeps 8.2 GB of dense weights in memory and streams 213 GB of routed experts and 114 GB of Engram tables from SSD. The bound is therefore two resources, and the SSD dominates:模型（552B 骨干 + 196B Engram）在任何量化下都无法驻留 48 GB 内存。转换后的检查点把 8.2 GB dense 权重常驻内存，213 GB 路由专家和 114 GB Engram 表从 SSD 流式读取。因此下限由两种资源决定，且 SSD 占主导：

3. Why the GPU-side changes could not work3. 为什么 GPU 侧改动注定无效

A replay microbenchmark executed each layer's captured decode kernels 20× back-to-back with a single evaluation at the end, isolating GPU execution from dispatch latency, syncs and SSD waits. Pure GPU work is 69 ms per token. The end-to-end 270 ms decomposes as follows:一个回放微基准把每层捕获的解码 kernel 连续执行 20 次、末尾一次求值，把 GPU 执行与派发延迟、同步、SSD 等待分离。纯 GPU 计算每 token 只有 69 ms。端到端 270 ms 的构成如下：

The sync is structural: which experts a layer needs is a GPU result, and the host must know it to issue SSD reads and assign cache slots before the expert matmul can be enqueued. Fusing elementwise kernels or merging matmuls shortens a 69 ms component that is already overlapped; it does nothing to the 201 ms that is not. The only lossless way to fill the SSD during the bubble is speculation, and its precision curve sets the ceiling:这个同步是结构性的：每层需要哪些专家是 GPU 计算结果，主机必须拿到它才能发起 SSD 读取并分配缓存槽位，之后才能排入专家矩阵乘。融合逐元素 kernel 或合并矩阵乘只缩短本已被重叠掉的 69 ms，对未重叠的 201 ms 毫无作用。气泡期间唯一能无损填充 SSD 的手段是推测预取，而它的精度曲线决定了上限：

  • K=4 is the knee: K=5 and K=6 add more wasted reads than useful ones on a saturated SSD (measured 265–287 ms and 331 ms).K=4 是拐点：在已饱和的 SSD 上，K=5、6 增加的无效读取多于有效读取（实测 265–287 ms 与 331 ms）。
  • Predicting two layers ahead is 92% precise for its top-2, yet every setting measured slower: the idle windows are already filled, so extra reads only delay the next layer's demand reads.提前两层预测的 top-2 精度有 92%，但各档位实测均变慢：空闲窗口已被填满，额外读取只会推迟下一层的需求读。
  • Predicting from the layer's output instead of its input is no more accurate (45.7% vs 45.9% coverage at K=3): attention determines routing.用本层输出代替输入做预测并不更准（K=3 覆盖率 45.7% vs 45.9%）：路由由 attention 决定。
  • A confidence filter on the 4th prediction trades recall for precision linearly (δ=0.1: wasted reads 0.53 → 0.37 per layer, recall −3 pts), with no knee worth shipping.对第 4 个预测做置信度过滤是线性权衡（δ=0.1：每层无效读 0.53 → 0.37，召回 −3 个百分点），没有值得实现的拐点。

5. What it would take to go further5. 继续提升需要什么

  • Remove the per-layer sync with a GPU-side slot table and speculative routing with verification (flash-moe style). Large change; the upstream author measured a 38% cost for speculative routing when SSD-bound.去掉每层同步：GPU 侧槽位表 + 带验证的推测路由（flash-moe 式）。改动大；上游作者实测 SSD 受限时推测路由开销 38%。
  • More memory raises the hit rate and lowers SSD bytes directly; a faster external SSD does not help (Thunderbolt 5 ≈ internal).更多内存直接提高命中率、减少 SSD 字节；更快的外置 SSD 无济于事（Thunderbolt 5 ≈ 内置）。
  • Lossy knobs, outside this report's constraint: --moe-topk 4 measured +38% decode; light code-calibrated expert pruning gives at most ~1.2× within a 0.5% accuracy budget (see the pruning analysis).有损开关（超出本报告约束）：--moe-topk 4 实测解码 +38%；在 0.5% 精度预算内的轻度代码校准专家裁剪最多约 1.2×（见裁剪分析）。

The API contract (OpenAI-compatible)API 契约（OpenAI 兼容）

curl -s http://127.0.0.1:8000/v1/chat/completions -H 'Content-Type: application/json' -d '{
  "model": "deepseek-flash",
  "messages": [{"role":"user","content":"用一句话介绍杭州。"}],
  "max_tokens": 128, "temperature": 0.7,
  "thinking": {"type":"disabled"}
}'
  • Always send max_tokens. Without it the default is 65536 tokens, which at ~3 tok/s can occupy the server for hours.一定要传 max_tokens。不传默认 65536，在约 3 tok/s 下一个请求可能占用服务器数小时。
  • Reasoning mode is on by default and forces temperature 1.0. For direct answers send "thinking":{"type":"disabled"}; for reasoning send {"type":"enabled"} plus "reasoning_effort":"low"|"high"|"max" (strings) and reserve ≥500 tokens; the reply carries reasoning_content.推理模式默认开启并强制 temperature 1.0。要直接回答传 "thinking":{"type":"disabled"}；要推理传 {"type":"enabled"} 并用字符串 "reasoning_effort":"low"|"high"|"max"，预留 ≥500 token；回复含 reasoning_content。
  • One request at a time (global lock); others queue. Set long client timeouts.同一时间只处理一个请求（全局锁），其余排队。客户端超时要设大。
  • Structured output: response_format {"type":"json_object"} or {"type":"json_schema","json_schema":{…}}. Tools: standard tools / tool_calls / role: tool. Images: image_url with a data URL or a public URL (loopback and private addresses are refused). Multi-turn: resend the conversation; the prefix cache is reused (usage.prompt_cache_hit_tokens).结构化输出：response_format 为 {"type":"json_object"} 或 {"type":"json_schema","json_schema":{…}}。工具调用：标准 tools / tool_calls / role: tool。图片：image_url 用 data URL 或公网 URL（拒绝回环与内网地址）。多轮：原样回传对话，前缀缓存会复用（usage.prompt_cache_hit_tokens）。
  • Also served: Anthropic-style POST /v1/messages and POST /v1/responses; point those SDKs at http://127.0.0.1:8000.同时提供 Anthropic 格式 POST /v1/messages 与 POST /v1/responses；对应 SDK 的 base URL 指向 http://127.0.0.1:8000 即可。
