DeepSeek-V4.1-Flash 在 Mac 上：本地推理 + DeepSeek Harness 终端 agent

一台 M4 Pro 48 GB MacBook 本地运行 552B 参数的 DeepSeek-V4.1-Flash：模型转换后 338 GB 放在 SSD 上，路由专家按需读取。再用 DeepSeek 官方的 DeepSeek Harness（minimal 配置）把它做成终端 agent：能读写本地文件、看图、搜索、读网页、处理需要登录的网站。日常使用只要一条命令；新 Mac 也是一条命令部署。

结论

  • 本地推理可用。默认 --fast 模式约 10 tok/s；无损模式约 4.5 tok/s，瓶颈在 SSD 读专家，不在 GPU 计算（计算路径上限 14.7 tok/s）。
  • Harness 用官方的 DeepSeek Harness minimal 配置。模型卡里它（DSH Minimal）的 DeepSWE 72.6、Terminal-Bench 2.1 90.6，高于 Claude Code 的 69.8 / 88.0；它本身的首轮提示只有约 710 token（加上本地的联网和浏览器工具后约 1,580），适合 prefill 受限的本机。
  • 终端体验。一条命令 dsv41：逐字输出、拖入或 @ 引用文件、剪贴板截图、沙箱限制写入、搜索与读网页、在专用 Chrome 窗口里登录后继续操作。
  • 主要瓶颈在前缀缓存。每个新会话第一轮要冷算约 1,580 token 的提示（首字约 30 s）；会话里有图片后每一步都不复用缓存（约 33 s）。同一会话的后续请求复用 84–99% 的提示，首字 4–20 s。

模型与引擎

官方 DeepInfer 只支持 NVIDIA SM100 和华为 Ascend，Mac 上不能运行，这里只把它当参考实现。实际引擎是社区的 MLX 移植 DeepInfer-Mac，加上本机做的 mk-1…mk-7 优化（融合 mxfp8 GEMV、MoE megakernel、两次 dispatch 的稀疏注意力、Engram 预取、GPU 热等待、解码循环重叠），细节见 MK_REPORT.html。

部分内容说明
模型DeepSeek-V4.1-Flash（1017，固定 revision 1bae0e1）；552B 骨干参数，40 层 CED，每层 384 个路由专家取 6 个多模态：自带 ViT，每张图最多 1,024 个 token

DeepSeek Harness 集成

"操作本地文件"不是模型能力，是 harness 的能力：模型输出工具调用，harness 在本机执行并回填结果。这里没有自己写 harness，用的是 DeepSeek 官方开源的 DeepSeek Harness（dsh）的 sdk-minimal 配置，也就是模型卡里的 "DSH Minimal"：一句话人设，加持久 bash、read_image、working_directory 三个工具。

终端里能做什么

输入

  • 从 Finder 拖文件进终端：路径里的空格转义、中文目录都能识别，图片直接给模型看
  • @path 引用文件（Tab 补全，按名称或路径）：文本内容随问题发送（超过 48 KB 只附开头），@file:40-80 只附这几行，@dir/ 附目录树
  • /paste：附上剪贴板里的截图

输出与会话

  • 逐字显示：思考灰色、回答正常色，工具调用和输出单独一行
  • /new /sessions /resume /effort off|low|high|max /browser on|off
  • Ctrl+C 中断：重启运行时并恢复会话
  • dsv41 -p "…" 一次性提问；dsv41 web 浏览器界面（默认 Minimal agent）

联网与登录

没有搜索工具时，模型会自己在 bash 里写脚本抓 Bing 结果页：能答对，但要 5 步、269 s，而且容易被反爬挡住。现在有三样工具：

工具来源做什么实测
mcp__web__searchharness/dsv41_tools.py（MCP）Bing，失败时换 DuckDuckGo；还原 Bing 跳转链接；不需要 API key1 次调用，64–68 s 答对
web_fetchDeepSeek Harness 自带本机匿名抓取网页正文，标注为不可信内容48–49 s 答对
mcp__browser__*harness/dsv41_tools.py（MCP + Playwright）本机 Chrome 的专用配置、可见窗口：open / read / screenshot / click / type / wait_for_login登录流程 91–93 s；截图 84–89 s

需要登录的网站怎么走

  1. agent 调 open 打开网址；遇到登录页（可见的密码框，或网址像登录页），工具结果会注明，Chrome 窗口切到前台。
  2. 终端用黄字提示 🔐，请你在那个窗口里登录。密码和两步验证只在浏览器里输入；agent 往密码框输入会被工具直接拒绝。
  3. agent 调 wait_for_login，每 2 s 检查一次，直到离开登录页（最多 600 s），然后返回登录后的页面正文和链接。
  4. 之后 agent 继续读页面、点击、填表、截图（截图直接作为图片给模型看）。登录状态保存在 ~/Models/dsh/browser-profile，下次不用再登录；会话结束时窗口关闭。

验收里用一个本地测试站模拟这个流程（harness/testdata/login_site.py）：浏览器打开 /login 后，测试脚本扮演用户调用 /approve，页面自己跳转，agent 读出受保护页面上的 4242。

部署与日常使用

新 Mac 一键部署（Apple Silicon，macOS 14+，内存 ≥ 32 GB，磁盘约 360 GB）
curl -fsSL https://raw.githubusercontent.com/longcheng-nv/TensorRT-LLM/deepinfer-mac-dsv41-flash/harness/install.sh | bash
日常使用
dsv41                     # 当前目录的终端 agent（需要时自动在后台启动模型服务）
dsv41 -p "问题"            # 问一句就退出
dsv41 --resume            # 继续本目录上次的会话
dsv41 web                 # 浏览器界面
dsv41 status | stop       # 查看 / 停止模型服务
dsv41 test                # 完整验收（15 项）
  1. 预检：Apple Silicon、macOS 版本、内存、Xcode 命令行工具。
  2. 代码与环境：uv → 克隆本分支 → 引擎环境、DeepSeek Harness 环境、联网工具环境，版本分别按 harness/constraints-*.txt 锁定 → 链接 ~/.local/bin/dsv41。
  3. 模型转换：要求接电源、不在 iPhone 热点上，下载默认绕过 shell 代理；中断后重跑同一条命令即可断点续传。
  4. 验收：doctor 确认 conversion complete，然后跑 dsv41 test --quick。

启动模型服务时，dsv41 先跑 doctor，专家缓存取 doctor 按当时空闲内存估计的值，并限制在 6–16 GB 之间；服务运行期间用 caffeinate 阻止空闲睡眠。所有组件和改动说明见 harness/README.md。

安全与隐私

  • 模型与数据不出本机。推理在本机完成；Web 版遥测设为 DISABLED，会话日志和插件清单不随请求上传。
  • 写入受限。bash 跑在 macOS Seatbelt 沙箱里，只能写启动目录和 /tmp；working_directory 工具切走目录也写不出去（已测）。需要时可以用 --full-access 放开，或用 --read-only 只读。
  • 浏览器隔离。使用和日常 Chrome 分开的专用配置，窗口可见；密码不经过模型。删掉 ~/Models/dsh/browser-profile 就等于全部退出登录。
  • 对外请求。搜索会把查询词发给 Bing / DuckDuckGo；web_fetch 和浏览器会访问你让它访问的网站。
  • 不可逆操作靠模型自觉。工具说明要求 agent 在付款、发消息、删除这类不可逆的提交之前先问你，但这不是强制拦截。只想让它看不想让它点，用 DSV41_BROWSER_ACTIONS=0。
  • DeepSeek Harness 还是开发者预览。官方说明它没有经过安全审计，所以这里固定在 0.2.2rc2；升级后要先跑一遍 dsv41 test。
