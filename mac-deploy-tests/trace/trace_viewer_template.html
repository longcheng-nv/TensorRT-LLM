01逐 token 汇总

每行一个 token，最后一行是平均。CPU 列为主线程各阶段在该 token 内的时长；GPU 忙 = 实测（非估计）GPU 区间的并集 ÷ 墙钟，「含估计」再并上 MoE 估计块，「其中保温」是 hot-wait 块单独的占比；SSD 忙 = 所有 IO 线程区间的并集 ÷ 墙钟；读盘请求按提交时刻归入 token；需求读延迟为提交 → 完成的中位数。点 token 名可在时间线上定位。

02怎么读

各泳道

  • Token / 层：上半格是 token 编号与墙钟，下半格按层交替着色；放大后显示层号。悬停可看 token 或层的时长。
  • CPU 主线程：每层依次是构建 → 构建路由图 → 路由同步 → 读回 → 提交命中 MoE → 下发读盘 → 等盘 → 提交未命中 MoE；token 末尾是 head 与采样。「路由同步」是在等 GPU，「等盘」是在等需求读。mk-7 起，有读盘的层先构建未命中 MoE 的图并返回，等盘挪到下一层的构建之后（等盘块落在下一层的构建与路由图之间）；第一个要等新读盘的层还会提交 Engram 值投影。
  • GPU（推断）：没有 GPU 时间戳。注意力块的结束是路由同步返回的时刻（实测），开始取提交时刻与上一块结束中较晚者；MoE、共享专家与 Engram 块的时长为估计（斜线、半透明）；等盘期间的灰块是 hot-wait 保温 kernel，用来防止 GPU 降频。
  • SSD IO：每行一个原生 IO 线程，每块约 2 MB，一个专家 15.5 MB 约 8 块。颜色按块开始时的优先级：需求读在前，推测预取低优先级； 表示该推测请求后来被提升为需求读， 表示被取消（剩余块不再读）。
  • 汇总表：与时间线同源，切换运行后一起更新；它也是本页的可访问数据视图。
